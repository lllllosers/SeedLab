# 科研数据与导出回归契约（含 200 份历史材料基线）

当前正式主程序为v0.5.1，唯一迁移head为d2e7a46b910c。200份历史材料已由独立importer正式导入目标电脑；精确实现、产物及历史验收提交统一见[v0.5.1 发布说明](releases/v0.5.1.md#importer与历史验收追溯)。

本文件是科研数据语义、科研工作簿及回归保护的唯一权威契约。main中的旧回填入口仅供回归测试创建一次性空业务库，不能用于生产。其测试夹具故意从进行中状态构造已完成/已终止场景；这不描述已投产历史实验的当前状态。测试数据、导出和备份不长期保存。AF-0 冻结现状，不运行正式生产 importer。

## Blank / 0 / NA 与计划 / 实际事实

| 状态 | 当前数据库事实 | 正式导出表达 |
| --- | --- | --- |
| 实测 0 | 有测定行，对应长度为数值 0，unavailable=false | 数值 0；不能转换为空白或字符串 NA |
| 尚无测定 | 有实际 SeedlingSample，但没有该 DAG 的 SeedlingMeasurement | 长度与实际测定时间空白；长表为“无测定记录” |
| 明确无法测量 | 有测定行，对应长度 NULL 且 unavailable=true | 长表数值空白、该项为“无法测量”；宽表该项为字符串 NA |
| 单侧无法测量 | 根或苗的一侧明确 unavailable，另一侧为实测值（可为 0） | 两侧独立保留，不能把整个测定行标为空或把另一侧改成 NA |
| 双侧无法测量 | 有实际测定行，两侧均 NULL / unavailable=true，实际时间必填 | 属于“已测定”；两侧宽表为 NA，不能变成无测定记录 |
| 尚无实际幼苗 | 只有计划槽位，没有实际 SeedlingSample | 发芽与测定事实空白；长表为“无实际幼苗”，不是实际幼苗上的缺测 |

**blank != 0 != NA；planned sample slot != actual SeedlingSample != actual SeedlingMeasurement。** 数据库每项只接受非负长度且 unavailable=false，或 NULL 且 unavailable=true；负值、未解决的空白、带数值的 unavailable、空实际测定时间均受当前约束保护。

measurement_slots 返回只读 dataclass 投影，空槽位不是 ORM fake row，不新增培养皿、幼苗或测定实体。无实际幼苗的材料保留于实验总体；实际幼苗不因没有测定消失。当前任务投影 measurement_query 从实际样本 × DAG 产生，与设计全集投影用途不同。

## 工作簿结构基线

正式科研工作簿由 workbook_export.build 生成，单实验与联合导出使用同一路径。以下 worksheet 名称及顺序、现有中文列名和列顺序均由完整表头回归测试冻结，不重新设计格式：

1. 01_材料总表：每份所选实验材料一行，保留系统物种/批次及原实验身份。
2. 02_发芽率汇总：仅以真实已置床种子为分母；没有巡检事实时累计与发芽率空白，明确巡检 0 才为 0。
3. 03_发芽原始记录：仅实际巡检事实，按培养皿重复、巡检时间排列，不虚构历史巡检。
4. 04_幼苗测定长表：计划 sample-DAG 槽位；每个实验只展开自身 DAG。
5. 05_幼苗测定宽表：计划幼苗槽位；RL/SL 按所选实验 DAG 并集升序生成，其他实验独有 DAG 留空。
6. 06_导出说明：版本、时间、所选实验和业务语义说明；导出时间是运行值，不固定为某次快照。

材料顺序使用 ordering.material_key：中文名完整拼音、学名、原始材料编号、系统批次编号；联合导出同键后用实验编号和材料身份稳定区分。汇总编号仅属于本次工作簿，不回写实验。材料内按计划重复/计划取样序号、DAG 排列；多重复 per_material 按实际发芽时间、重复、皿内样本序号匹配。业务编号与内部 UUID / dish code 分离，正式表不导出后两者。

completed / cancelled 都保留上述设计、事实、0、NA 和空白；结束状态仅关闭当前执行待办，不能改变科研输出。

## 使用方法

入口为 `scripts/maintenance/backfill_legacy_200_species.py`。只接受系统临时目录内已经迁移到当前版本的 `.db` 测试库，并要求该库已有唯一可用的负责人。自动测试夹具会在新建的临时目录准备迁移和测试负责人；工具本身不读取应用的默认数据库，不初始化或清空业务库。

```powershell
# 在仓库根目录执行；以下目标必须先准备为空业务临时测试库。
$legacySource = (Resolve-Path -LiteralPath '.\dist\delivery-v051\种子发芽试验结果统计(11).xlsx').Path
$testDatabase = Join-Path $env:TEMP 'seedlab-legacy-test\seedlab.db'
& .\.venv\Scripts\python.exe scripts\maintenance\backfill_legacy_200_species.py --source $legacySource --database $testDatabase --owner legacy-test-owner

# 仅当只读核验通过后，明确写入临时测试库。
& .\.venv\Scripts\python.exe scripts\maintenance\backfill_legacy_200_species.py --source $legacySource --database $testDatabase --owner legacy-test-owner --apply
```

`--data-root` 可替代 `--database`，仅表示系统临时目录中的测试目录，数据库文件为该目录下的 `seedlab.db`。含运行配置的目录和名为 SeedLabData 的目录被拒绝。目标必须关闭其他连接、完成 WAL 写入后再核验。

默认 dry-run 使用 SQLite immutable 只读连接，不改数据库，也不创建 WAL/SHM 文件；它核验源数据、迁移版本、负责人和空业务状态。apply 在一个事务中创建数据，数量核账、逐值核账及正式工作簿反向核账全部通过后才提交；任一失败均回滚。已导入的测试库再次执行时被拒绝，不覆盖、不追加重复历史数据。

## 正式结果结构与完整度

数据库保存真实事实：200个 ExperimentMaterial、1665个 SeedlingSample、4955个 SeedlingMeasurement、3个 MeasurementTimepoint。数据库不会增加为2000株幼苗或6000条测定。

结果表保存“实验设计全集 × 真实事实”。历史协议每皿取前10株、单重复，故宽表为200 × 10 = 2000个计划幼苗槽位；长表为2000 × 3 = 6000个计划测定槽位。导出中的空计划槽位是只读投影，不是数据库实体，也不代表最终未获得幼苗。

## 可复用槽位与后续分析契约

`app.services.measurement_slots.build_measurement_dataset` 是 AF-4 长表、宽表和未来 Analysis 共用的中立只读入口。它委托既有 build_measurement_slots 完成计划匹配算法，再输出 contracts/measurement_dataset.py 的 frozen dataclass / tuple：MeasurementSlot、MeasurementStage、MeasurementDatasetRow、MeasurementDataset。内部旧槽位投影仍可用于兼容回归，但新消费方取得的数据不携带 ORM 或 Session。两者均不写库、不构造假的 ORM 实体，不引入观察结束、等待发芽、漏测或最终失败等生命周期判断。

- 读取现有协议的 sampling_rule、sample_count、sample_scope、replicate_count 和材料覆盖值；不硬编码通用材料的取样数。
- 每皿取样按计划重复分别展开。未建立、未置床或已取消的培养皿仍属于原设计；导出保留槽位及计划重复，不添加数据库培养皿。
- 每材料取样在多个培养皿间共用一个取样上限，不乘重复数。真实样本按发芽时间、重复、皿内序号稳定匹配，保留既有现场身份；空槽位只保留计划取样序号，不预分配真实培养皿。单重复时按原皿内序号匹配，保留缺号。
- 尚未确认现场编号时，现场编号留空，用本次汇总编号、计划培养皿重复和计划取样序号识别设计位置。跨皿共用取样数时计划培养皿重复为空。
- 设计信息不足或实际样本、重复、测定节点与方案不一致时，提示先核对方案和记录，拒绝静默删掉事实或材料。
- “是否已有实际幼苗”仅为“是/否”。长表“数据状态”仅为“已测定/无测定记录/无实际幼苗”；存在测定但明确无法测量仍属于“已测定”，具体项显示无法测量或NA。“无测定记录”仅表示当前没有记录，不等于漏测。

任何后续 analysis-ready dataset 必须从 `ExperimentMaterial × planned sample slots × planned timepoints` 构造，再 LEFT JOIN 真实 SeedlingSample 与 SeedlingMeasurement。不能直接把后两者当作实验总体起点，否则没有实际数据的材料会从分析母体中消失。

例如0株材料仍应保留 planned_n=10、obtained_n=0、measured_n=0；均值与SD为NA/空白。没有数据、材料不存在、人为剔除是不同事实。本轮仅锁定可复用骨架和契约，不实现物种汇总、PCA、AGR/RGR或其他统计分析。

AF-4 明确 Raw Fact → Canonical Dataset → Future Statistical Result；最后一层未实现。未来 exclusion 只能叠加为 Raw Fact + Exclusion Overlay → Analysis Dataset / Statistical View，不能删除或改写原始测定。当前没有 exclusion 表、迁移、API、算法或界面。

dataset 的 measurement_id 显式表示实际记录是否存在；无记录时两侧长度及 unavailable 均为 None，有记录时各侧布尔状态和 Decimal 数值完整保留。内部 sample_id、dish_id 只用于关联；正式导出继续只使用业务身份。read_dataset 只接受注入的 DatasetReader.read，Analysis 不导入 GER ORM、写服务、API 或 HTTP。

新增 test_measurement_dataset.py 验证只读 SQLite 连接、全部原始表内容不变、Session 不 autoflush、脱离 ORM 后可读、嵌套不可变、计划匹配与排序。六个小型场景及历史 200 工作簿的全部六表内容 SHA 在 AF-4 改动前取得并用于改动后比较，只排除动态导出时间；不保存源码、数据库或工作簿副本。既有表头、逐值核账、动态 DAG、跨重复设计和生命周期导出测试继续生效。

## 已结束实验的历史事实与当前待办

v0.5.1 将计划槽位统计与当前任务统计分开。只有进行中实验产生巡检和测定待办；已完成、已终止实验的当前巡检、今日待测、逾期、后续和无法安排任务计数均为 0，任务列表（包括“全部有任务”）为空。已结束实验仍通过测定记录查看真实测定，计划槽位和缺失事实保持不变。

历史回归夹具分别构造已完成和已终止状态。已完成历史实验可以保持 `ended_at = NULL`，不伪造结束时间。两种状态都保留 200 份材料、198 个物种、1665 株实际幼苗、4955 条测定、40 个实际幼苗未测槽位及 2000 / 6000 行正式导出；无巡检的发芽汇总仍为空，数值 0 不改变。

正常“完成实验”仍使用未遮蔽的槽位事实统计，进行中实验有待置床培养皿或真实测定待办时仍被阻止。AF-0 不修改完成判据；生产导入已由独立importer完成，未来干重补录尚未实现。

## 自动测试

原始文件不提交 Git。设置 `SEEDLAB_LEGACY_SOURCE` 后启用原文件集成测试（包括已结束历史实验场景）；未设置时仅跳过依赖原文件的测试，其余发芽语义、导出和临时库保护测试正常执行。

```powershell
$env:SEEDLAB_LEGACY_SOURCE = (Resolve-Path -LiteralPath '.\dist\delivery-v051\种子发芽试验结果统计(11).xlsx').Path
$testRoot = Join-Path $env:TEMP ('SeedLab-check-' + [guid]::NewGuid().ToString('N'))
Set-Location backend
& ..\.venv\Scripts\python.exe -m pytest -q --basetemp=$testRoot
Set-Location ..\frontend
npm test
npm run build
```
