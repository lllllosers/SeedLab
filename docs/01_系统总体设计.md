# 系统总体设计

SeedLab 是课题组内部的长期实验数据工作空间。当前稳定生产版本为 v0.5.1，已支持材料台账、GER 种子萌发试验、幼苗根苗长测定、科研工作簿、账号审计及 Windows portable。本文是架构唯一权威概览；具体业务规则、schema 和运维操作分别从[文档导航](README.md)进入。

## Current Architecture：当前实现

~~~text
Vue 3 / TypeScript / Pinia / Vue Router
    │ 同源 /api；开发由 Vite 代理
FastAPI routers（api）
    │ 权限与 HTTP 错误映射；置床清单 XLSX 仍在 API
    ├──→ contracts（Experiment / GER / Measurement Pydantic 契约）
业务服务（services） ──→ contracts；↔ SQLAlchemy entities（models）
    │                      │
    └──────────────── SQLite WAL
                           ↑
                     Alembic migrations

AF-1 源码 runner / 后续冻结服务器 → app.server_entry
    → database_upgrade（兼容性、检查、按需快照）→ 既有 Alembic → 验证 → FastAPI/Uvicorn
Windows Control Center → 显式 RuntimePaths / 实例探测 / 进程 / SQLite backup
~~~

后端当前按 api、core、db、models、services 分目录，尚未按实验类型拆成独立模块。所有业务 ORM 实体仍集中在 models/entities.py；core/experiment_types.py 定义当前类型元数据、workflow Protocol 与不可动态注册的 registry；experiment_composition.py 静态组装唯一 GER 注册。Literal 输入范围继续保持 GER，以保留现有校验和 OpenAPI。应用 lifespan 绑定自己的 Session，导入模块不创建默认数据库；应用不自动建表，迁移只经 Alembic。

| 当前范围 | 真实入口与调用关系 |
| --- | --- |
| 平台与资源库 | core/auth、bootstrap、config 与 api/catalog、material_import；物种及种子批次是长期材料身份 |
| 实验配置 | api/experiments → Core identity/lifecycle；api/configuration → germination_config，GER 拥有方案、材料覆盖和 DAG |
| GER 执行 | api/execution → sowing_workflow、germination_execution；编号确认生成未置床计划皿，真实置床启动实验，巡检同事务生成前 N 株 |
| 幼苗测定 | api/measurement → seedling_measurement、measurement_query；从实际样本 × DAG 派生任务，SQL 分页/聚合，Python 校验写入 |
| 科研导出 | api/workbook_export → workbook_export → measurement_slots.build_measurement_dataset；长表与宽表共用不可变、脱离 ORM 的契约 |
| Analysis 只读边界 | analysis.datasets.read_dataset → 注入的 DatasetReader.read；只接收 MeasurementDataset，不依赖 ORM、Session、写服务或 HTTP |
| 生命周期 | experiment_lifecycle 为正式 status、started_at、ended_at、termination_reason 的唯一生产写入 authority；通过 registry 获取 GER 决策 |
| 审计 | services/application_support.record 随业务事务保存 AuditLog，common.record 保留兼容引用；audit_history 提供分页及业务身份，读取不新增审计 |
| 运维 | app/server_entry 和部署初始化共用 services/database_upgrade；现有 migration chain 不变，sqlite_backup 提供按需恢复点，database_recovery 提供停服后的显式恢复 |
| 前端 | app/routes 组装原路由；experiments 负责身份契约、列表与静态 UI 分发；germination 拥有 GER 创建、配置和执行；measurement 拥有工作台、根苗长录入和记录；shared 提供单一 transport、格式化和公共控件 |

Python 材料排序及现场编号以 services/ordering.py 为单一权威来源。测定 SQL 使用该模块的编号表达式；SQL 查询按实验内编号、重复、皿内样本和 DAG 排序。中文名完整拼音的目录/材料排序当前在 Python 完成，没有第二套 SQL 拼音排序。

## AF-2：契约与依赖规则

`app/contracts/experiments.py`、`germination.py`、`measurement.py` 是当前 20 个增长域 DTO 的唯一定义；`base.py` 保存共享 ORMModel。API 与服务直接引用同一类型；`api/schemas.py` 仅兼容重导出这些类型，保留 Auth/Catalog 的原定义。字段、required/optional、默认值、校验与序列化不变；ProtocolInput 仍表达当前 GER 方案，不代表已拆分 Experiment Core。

增长域服务禁止依赖 `app.api.*`、FastAPI/Starlette、`app.main`、认证/Web adapter 或含 HTTP 兼容包装的 `services/common.py`。当前显式名单为 germination_config、germination_workflow、experiment_identity、experiment_lifecycle、germination_execution、sowing_workflow、seedling_measurement、measurement_query、measurement_slots、measurement_schedule、workbook_export、application_support。Contracts 同样不能依赖 API、services、models 或 db。新增增长服务时必须同步扩充架构测试名单，不能以换目录规避边界。

`contracts/errors.py` 只有 ApplicationError 及 NotFoundError、ConflictError、ValidationError；它们保存原业务 detail，不含 HTTP 状态。`api/errors.py` 分别映射为原 404、409、422，并复用 FastAPI 响应处理器。未分类异常保持服务器失败；请求体校验、Auth/CSRF 和 API 自身的 HTTPException 保持原路径。

`application_support.py` 提供事务、实体查找与审计实现，不依赖 transport；`common.py` 为本阶段未迁移的 Catalog/System 等调用者保留旧 HTTP 包装，并委托同一实现，避免重复事务逻辑。这里只移动错误边界，不统一整个项目的异常体系。

AF-2 只调整异常及 DTO 边界，未改动计划/事实、DAG、SQL、Excel、排序和业务状态算法。当前 registry、生命周期 authority、Analysis port 及前端 feature 已由 AF-3—AF-5 落实，分别见下文。

自动防回流见[架构依赖测试](../backend/tests/test_architecture_dependencies.py)，DTO 身份、选择性 OpenAPI 与 HTTP 状态/detail/headers 回归见[业务契约测试](../backend/tests/test_growth_contracts.py)。完整 OpenAPI 可在临时内存中比较，无需维护巨型快照文件。

## AF-3：Experiment Core / GER 所有权

Core 拥有 Experiment 稳定身份、类型、名称、owner、通用材料参与关系、生命周期状态和开始/结束/终止原因。GER 拥有默认方案与覆盖值、编号确认/解除、培养皿、巡检、first-N、germinated_at、DAG，以及就绪、完成资格、事实存在和清理判断。原 experiment_config 已移为 germination_config，内部业务算法保留。

`core/experiment_types.py` 的 ExperimentTypeWorkflow 只抽象目前需要的可编辑、PATCH 约束、就绪、完成检查/资格、事实存在及未使用设计清理。Core 不导入 GER 配置、执行、测定实现或 GER ORM；GER 可以依赖 Core 接口及生命周期服务。现有 models/entities.py 保持集中注册，不做表或字段搬迁。

`germination_workflow.germination_registration()` 提供 GER 的 code、原 label 与 workflow；`experiment_composition.build_experiment_registry()` 是唯一静态组装入口，由 create_app 绑定到应用实例。registry 构造时拒绝重复或不匹配的类型元数据，公开接口只提供确定性的 entries 和 require，没有运行时注册/插件扫描。EXPERIMENT_TYPES 保留只读名称兼容视图；GET /api/experiments/types 仍返回原 value/label。没有数据库类型表、第二类型或未来能力占位。

`services/experiment_lifecycle.py` 是唯一正式状态及时间戳写入 authority：update/set_status、reopen_after_cleanup、activate_from_fact、correct_started_at、complete、terminate。GER 负责验证和修改自己的事实，再调用 Core，沿用同一事务及既有审计形状；专用完成/终止与 PATCH 快照仍保持原差异。未使用实验删除时，Core 通过 workflow 检查事实并清理 GER 行，再删除通用材料关系及 Experiment。

首次有效置床只把 ready 转为 active 一次；后续较晚置床不改 started_at。补录更早事实或实际置床时间纠错仍按既有契约维护最早真实置床时间，不冻结成首次录入时间。ORM 默认草稿、测试 fixture、既有 migration 与独立历史 importer/backfill 的历史赋值不属于在线正式 lifecycle 入口，保持原样。

边界及写入保护见[架构测试](../backend/tests/test_architecture_dependencies.py)，静态组装见[registry 测试](../backend/tests/test_experiment_registry.py)，首次置床、审计与跨边界回滚见[lifecycle authority 测试](../backend/tests/test_lifecycle_authority.py)。AF-3 没有改变 Measurement/DAG/Excel 算法及前端目录；AF-4 的读取边界见下节。

## AF-4：Measurement / Dataset / Analysis 边界

`models/entities.py` 中的 SeedlingSample、SeedlingMeasurement、GerminationObservation 是原始实验事实。根苗长与两侧独立 unavailable 继续使用强类型字段及现有数据库约束，不改为 EAV。`services/measurement_slots.py` 的既有 build_measurement_slots 负责设计全集与真实事实的匹配、验证和稳定顺序，算法保持；新增 build_measurement_dataset 只把结果转为中立不可变契约，不造假 ORM 行、不增删改事实。

`contracts/measurement_dataset.py` 定义 MeasurementSlot、MeasurementStage、MeasurementDatasetRow、MeasurementDataset。槽位保存实验/材料、计划序号/重复、实际皿/幼苗身份与现场编号；行保存 DAG、计划日期、测定是否存在、Decimal 根苗长、独立 unavailable、实际时间和备注。所有容器为 tuple、节点为 frozen dataclass，返回值不携带 ORM 或 Session。缺测的 unavailable 为 None；已有测定的 false/true 保留，数值 0 不变。内部身份仅供关联，不增加用户展示或导出字段。

科研工作簿消费同一 dataset；材料及巡检表继续使用既有事实查询。measurement_query 的实际幼苗 × DAG SQL 投影服务当前任务、履历和分页，不扩成计划总体，也不改成 Python 循环；没有实际幼苗的材料由完整 dataset 保留。api/execution 的实际幼苗列表查询移到 germination_execution.list_samples，原 SQL、编号及响应保持；置床清单与其他 HTTP adapter 不在本次移动范围。

`analysis/datasets.py` 仅定义结构化 DatasetReader.read port 和 read_dataset；数据库适配器 MeasurementDatasetReader 位于 measurement_slots，由边界外调用者注入。Analysis 只依赖中立契约和标准库，不能导入 GER ORM、服务实现、API、FastAPI/Starlette 或 SQLAlchemy。Core、GER 与 Measurement 服务不能依赖 Analysis；投影禁止事实写入和 ORM 构造，架构测试包含违规注入保护。没有统计 consumer、算法、结果表或 API，也没有 statistics/anova/outliers 空壳。

`measurement_schedule.py` 集中陈述 DAG 的本地自然日语义，同时保留 Python scheduled_date 和 SQLite scheduled_date_expression 两个执行实现；旧 seedling_measurement.scheduled_date 兼容引用仍可用。SQLite 本地日期 UDF 沿用 local_time，日期加法仍由 SQL 完成，查询分页与聚合不变。测试覆盖 DAG 0/3/7/14、本地午夜、不同偏移、时间分量、闰日、跨月年、夏令时和无发芽时间，并比较 dataset、Python 与 SQL 结果。

三层语义为 Raw Fact → Canonical Dataset → Future Statistical Result；第三层未实现。未来剔除只能是原始事实加独立 exclusion overlay 后形成分析视图，不能删除原始测定；AF-4 没有 overlay 表、迁移、接口或算法。科研回归及三层事实语义统一见[14](14_历史数据与导出回归契约.md)，业务写入政策继续以[08](08_幼苗测定业务规则.md)为准。

## AF-5：前端 feature 所有权与静态分发

真实代码位于 `frontend/src/app`、`shared` 和 `features/{experiments,germination,measurement}`。Catalog、Audit、Admin、Auth 页面继续保留在 views，layout、router 基础设施和 auth store 保持现有等价位置；没有空的 analysis 或其他占位 feature。旧文件已移动并更新全部引用，没有新旧两套组件或转发 wrapper。

| 前端范围 | 实际职责与公开入口 |
| --- | --- |
| app / router | app/routes.ts 组装全部业务路由；router/index.ts 保留 Web History、初始化、登录、强制改密及管理员 guard |
| shared | api/client.ts 为唯一 API transport，保留 session/CSRF/错误映射；format.ts、Paged、PageBackButton 与 useClientPagination 不依赖 feature |
| experiments | index.ts 公开身份 DTO 和实验 routes；列表、基础读取 client、navigation 及创建/配置/执行 dispatcher 不导入 GER 私有实现 |
| germination | index.ts 公开 GER DTO、材料导入预选入口与 germinationUi；拥有原创建七步、方案与覆盖、编号、置床、巡检、样本进度和执行页面 |
| measurement | index.ts 公开 Measurement DTO 与 SeedlingMeasurementWorkbench；拥有工作清单、录入、编辑、历史表与记录查询、根苗长独立 NA/blank/0 和已完成纠错 UI |

原配置页含基础描述编辑与状态按钮，继续作为 GER 配置复合页面展示通用 Experiment 契约，不拆改用户操作。允许保留按钮可见性、状态名称及后端 completion-check 响应展示；就绪、启动、完成、终止等业务资格仍由 AF-3 后端决定，前端不建立第二套状态机。跨 feature 引用经过明确 public entrypoint；Measurement 只引用 Experiment 公共身份/状态契约和 shared，GER 执行页通过 Measurement 公共入口组合工作台。

`features/experiments/uiRegistry.ts` 是唯一 UI 静态组装处，经过 GER public entrypoint 映射唯一 `GER`（种子萌发试验）的 create、configuration、execution loader 和实际使用的执行路径。它只表达当前 bundle 的渲染能力，不替代后端 registry，不提供运行时注册、扫描、远程插件或数据库元数据。创建继续读取 `/api/experiments/types` 的选择项，详情及执行 dispatcher 先读取现有 Experiment identity API 的 experiment_type，再加载相应页面；因此详情/执行各增加一次既有只读身份请求，后续 GER 请求和所有 HTTP 契约保持原样。未知、空值和原型名称都不能默认进入 GER，复用既有错误及返回列表文案显示不可用状态。

URL、路由名称、嵌套、query、菜单、文案、template 和 CSS 保持；`/experiments/new`、`/experiments/:id`、`/experiments/:id/germination?tab=measurement` 继续可直接打开和刷新。类型定义仅按所有权移动，现有 wire 字段及 GER Literal 保留，没有 schema 生成工具。19 个迁移页面/组件的 template/style 内容摘要保护现有输出；架构测试用 AST 检查导入和生命周期判定，并以违规 fixture 证明拒绝有效。测试与运行方式见[开发说明](04_开发与运行说明.md)。

以下是当前代码的逻辑所有权，不要求物理目录改为 modules，也不代表新表或 API。**Logical ownership != physical schema。** AF-1—AF-5 的边界已落实；AF-6 只补完整业务链与退役 importer 运行依赖保护，保留正式 v0.5.1 EXE/ZIP。各范围的真实入口已列于本文开头；中立 contracts、静态组装和业务服务可在现有目录定位。
