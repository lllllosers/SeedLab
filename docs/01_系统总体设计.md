# 系统总体设计

## 目标与边界

SeedLab 是课题组内部的长期实验数据工作空间。Stage 0 面向约 2–3 人、私人 Windows 主机和局域网浏览器，建立可靠的数据身份、审计、账号和基础页面。当前不实现正式发芽巡检、根苗长录入或分析计算。

## 架构

```text
浏览器（Vue 3 / Vite）
    │ /api，开发时由 Vite 代理
FastAPI API → 业务服务 / SQLAlchemy → SQLite（WAL）
                                  ↕
                            Alembic migrations
```

后端按 `api`、`core`、`db`、`models`、`services` 分工。API 处理输入输出和权限，服务函数处理编号、审计和持久化边界；模型定义关系与数据库约束。应用启动不自动创建表，结构变更仅走 Alembic。

前端由路由守卫恢复会话，Pinia 保管当前用户和 CSRF token，Axios 对修改请求附带该 token。所有业务请求由 Vite 的同源代理转发。页面按工作台、资源库、实验和系统组织。

## 身份与权限

用户通过用户名与 Argon2 密码登录；服务端保存随机会话令牌的 SHA-256 摘要，浏览器只持有 HttpOnly、SameSite=Lax Cookie。修改请求必须带登录返回的 `X-CSRF-Token`。当前只有管理员和普通成员两级；管理员可以创建用户。没有公开注册。生产环境应使用 HTTPS、`SEEDLAB_COOKIE_SECURE=true` 和可信的反向代理。

## 数据与追溯

所有实体以 UUID 为永久身份；`SP-0001`、`LOT-YYYY-001`、`EXP-YYYY-001` 是用户可见编号。编号分配使用数据库唯一约束保护；并发撞号时返回 409，客户端可重试。创建、修改、删除与导入写入 `AuditLog`，保留变更前后快照。普通读取不写日志。

Excel 仅用于数据交换。数据库是唯一事实来源；目前支持物种 `.xlsx` 导入和 CSV 导出。导入检验学名与规模，整批提交。

幼苗根苗长的测定节点采用 DAG（Days After Germination，单株实际发芽后的天数），而非培养皿置床后的天数。`MeasurementTimepoint.day_after_germination` 定义实验计划中的非负 DAG 节点；未来测定任务以各株 `SeedlingSample.germinated_at` 为基准计算。培养皿仍记录 `sown_at`；发芽巡检若需置床后天数，应由该时间派生。Stage 0 只建立模型，不生成任务。

## 当前限制

本阶段还没有生产部署封装、自动备份、密码重置、精细权限或外部访问网关。SQLite WAL 适合目前的小规模访问，但不能替代备份。导入与列表接口目前限制单次 500 行/500 条，后续数据增长时应添加分页与导入预览。
