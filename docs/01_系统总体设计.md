# 系统总体设计

## 目标与边界

SeedLab 是课题组内部的长期实验数据工作空间。Stage 0 建立可靠的数据身份、审计、账号和基础页面；Stage 1 提供完整实验配置向导、配置详情与工作量估算；Stage 2 将已就绪实验投入执行，支持培养皿与发芽巡检。根苗长录入和统计分析留待后续阶段。

## 架构

```text
浏览器（Vue 3 / Vite）
    │ /api，开发时由 Vite 代理
FastAPI API → 业务服务 / SQLAlchemy → SQLite（WAL）
                                  ↕
                            Alembic migrations
```

后端按 `api`、`core`、`db`、`models`、`services` 分工。API 处理输入输出和权限；实验配置服务统一计算 effective 值、校验取样容量、规范化 DAG 和估算工作量；执行服务负责原子开始、巡检与前 N 株取样；模型定义关系与数据库约束。应用启动不自动创建表，结构变更仅走 Alembic。

前端由路由守卫恢复会话，Pinia 保管当前用户和 CSRF token，Axios 对修改请求附带该 token。所有业务请求由 Vite 的同源代理转发。页面按工作台、资源库、实验和系统组织。

## 身份与权限

用户通过用户名与 Argon2 密码登录；服务端保存随机会话令牌的 SHA-256 摘要，浏览器只持有 HttpOnly、SameSite=Lax Cookie。修改请求必须带登录返回的 `X-CSRF-Token`。密码长度为 8 至 128 位，不强制字符类别。数据库尚无用户时，服务器本机生成高熵一次性初始化码，浏览器 `/setup` 可创建首个管理员；成功后入口关闭。当前只有管理员和普通成员两级；管理员创建成员时设置临时密码。成员首次登录必须改密，后端阻止其访问业务 API。改密、重置密码和停用会清除相关会话。没有公开注册。详见[账号初始化与权限管理](07_账号初始化与权限管理.md)。生产环境应使用 HTTPS、`SEEDLAB_COOKIE_SECURE=true` 和可信的反向代理。

## 数据与追溯

所有实体以 UUID 为永久身份；`SP-0001`、`LOT-YYYY-001`、`EXP-YYYY-001` 是用户可见编号。编号分配使用数据库唯一约束保护；并发撞号时返回 409，客户端可重试。创建、修改、删除与导入写入 `AuditLog`，保留变更前后快照。普通读取不写日志。

Excel 仅用于数据交换。数据库是唯一事实来源；目前支持物种 `.xlsx` 导入和 CSV 导出。导入检验学名与规模，整批提交。

幼苗根苗长的测定节点采用 DAG（Days After Germination，单株判定发芽后的天数）。`MeasurementTimepoint.day_after_germination` 定义实验计划中的非负 DAG 节点；未来测定任务以各株 `SeedlingSample.germinated_at` 为基准计算。该时间来自首次判定发芽的巡检，并非真实生理发芽瞬间。培养皿仍记录 `sown_at`；巡检所需置床后天数由该时间派生。Stage 2 不生成根苗长任务。

实验配置由 `ExperimentProtocol` 保存默认参数，`ExperimentMaterial` 用可空覆盖值保存材料差异。配置时动态推导每个材料的有效粒数、重复数和取样数；`NULL` 意味着继承默认值。`draft` 与 `ready` 允许调整结构，`active` 及终态阻止结构性修改。详细规则见 [实验配置业务规则](05_实验配置业务规则.md)。

正式开始实验在一个事务中生成全部培养皿并切换为 `active`。巡检只存完整时间和本次新增，累计及发芽率实时派生；样本选取与巡检同事务提交。详细规则见 [发芽实验执行业务规则](06_发芽实验执行业务规则.md)。

## 当前限制

本阶段还没有生产部署封装、自动备份、自助找回密码、精细权限或外部访问网关。SQLite WAL 适合目前的小规模访问，但不能替代备份。导入与列表接口目前限制单次 500 行/500 条，后续数据增长时应添加分页与导入预览。
