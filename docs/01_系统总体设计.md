# 系统总体设计

## 目标与边界

SeedLab 是课题组内部的长期实验数据工作空间。Stage 0 建立可靠的数据身份、审计、账号和基础页面；Stage 1 提供完整实验配置向导、配置详情与工作量估算；Stage 2 将已就绪实验投入执行，支持培养皿与发芽巡检。Stage 3 已完成 DAG 任务、根苗长录入、历史查询、纠错、生命周期与审计，并随 v0.4.0 正式发布；统计分析留待 Stage 4。

## 架构

```text
浏览器（Vue 3 / Vite）
    │ /api，开发时由 Vite 代理
FastAPI API → 业务服务 / SQLAlchemy → SQLite（WAL）
                                  ↕
                            Alembic migrations
```

后端按 `api`、`core`、`db`、`models`、`services` 分工。API 处理输入输出和权限；实验配置服务统一计算有效值、校验取样容量、规范化 DAG 和估算工作量；置床服务负责编号确认、分批置床和取消，执行服务负责巡检与前 N 株取样；模型定义关系与数据库约束。应用启动不自动创建表，结构变更仅走 Alembic。

前端由路由守卫恢复会话，Pinia 保管当前用户和 CSRF token，Axios 对修改请求附带该 token。开发请求由Vite同源代理转发，生产页面与API由同一个FastAPI端口提供。页面按工作台、资源库、实验和系统组织。

## 身份与权限

用户通过用户名与 Argon2 密码登录；服务端保存随机会话令牌的 SHA-256 摘要，浏览器只持有 HttpOnly、SameSite=Lax Cookie。修改请求必须带登录返回的 `X-CSRF-Token`。密码长度为 8 至 128 位，不强制字符类别。数据库尚无用户时，服务器本机生成高熵一次性初始化码，浏览器 `/setup` 可创建首个管理员；成功后入口关闭。当前只有管理员和普通成员两级；管理员创建成员时设置临时密码。成员首次登录必须改密，后端阻止其访问业务 API。改密、重置密码和停用会清除相关会话。没有公开注册。详见[账号初始化与权限管理](07_账号初始化与权限管理.md)。生产环境应使用 HTTPS、`SEEDLAB_COOKIE_SECURE=true` 和可信的反向代理。

## 数据与追溯

所有实体以 UUID 为内部永久身份，不向普通用户展示；物种 `SP-0001` 全局流水，批次 `LOT-YYYY-001` 按年流水，新实验 `GER-YYYYMM-001` 按类型和月份流水。独立实验类型当前为 GER（种子萌发试验），创建后不可改。实验年月优先取计划开始日期，未填时取实验室时区（默认 Asia/Shanghai）当前年月；旧 `EXP-YYYY-001` 实验编号保留。编号与名称、日期、当前排序分离，创建或锁定后不自动改变。培养皿展示现场编号 001 / 001-1，幼苗展示完整编号 001-01 / 001-1-01，内部培养皿长 code 不用于普通界面、业务搜索和正式导出。编号分配使用数据库唯一约束保护；并发撞号时回滚整个请求并返回 409，客户端可重试。创建、修改、删除与导入写入 `AuditLog`，保留变更前后快照。普通读取不写日志。

Excel 仅用于数据交换。数据库是唯一事实来源；目前以中文种子材料清单统一 `.xlsx` 预检和确认导入，原子提交；支持实验数据工作簿与物种/批次基础台账导出。

科研结果导出以实验材料全集、有效取样方案和各实验配置的 DAG 构造只读计划槽位，再匹配真实幼苗与测定；宽表按计划幼苗、长表按计划幼苗与 DAG 展开。没有实际幼苗的材料仍保留设计位置，空槽位不写库；未来统计分析也必须从设计全集 LEFT JOIN 真实事实。没有发芽巡检时累计发芽数和发芽率为空，明确巡检 0 才表示已检查且无发芽。历史200份材料已正式导入目标电脑并核账；源码测试仍使用隔离数据库。见[历史回归契约](14_历史数据与导出回归契约.md)与[importer维护索引](11_历史生产导入维护工具.md)。

幼苗根苗长的测定节点采用 DAG（Days After Germination，单株判定发芽后的天数）。`MeasurementTimepoint.day_after_germination` 定义实验计划中的非负 DAG 节点；测定任务以各株 `SeedlingSample.germinated_at` 为基准计算。该时间来自首次判定发芽的巡检，并非真实生理发芽瞬间。培养皿仍记录 `sown_at`；巡检所需置床后天数由该时间派生。测定任务由样本与时间点实时派生，不存冗余任务表。

实验配置由 `ExperimentProtocol` 保存默认参数，`ExperimentMaterial` 用可空覆盖值保存材料差异。配置时动态推导每个材料的有效粒数、重复数和取样数；`NULL` 意味着继承默认值。`draft` 与未确认编号的 `ready` 允许调整结构，确认编号后须在未置床时先解除确认；`active` 及终态阻止结构性修改。详细规则见 [实验配置业务规则](05_实验配置业务规则.md)。

确认置床编号在一个事务中固定材料编号并生成尚未置床的培养皿；第一批实际置床使实验切换为 `active`，开始时间取最早实际置床时间。巡检只存完整时间和本次新增，同一批次共享一个巡检时间；累计及发芽率实时派生，样本选取与巡检同事务提交。材料一体导入先预检再原子确认；联合导出只在工作簿中生成汇总编号。详细规则见 [发芽实验执行业务规则](06_发芽实验执行业务规则.md)。

## 当前限制

v0.4.1 已提供生产部署封装、运行控制中心、portable 和正式业务数据库在线备份；数据库恢复、升级器、自助找回密码和精细权限尚未实现。远程 HTTPS 入口依赖用户配置的外部隧道，真实公网环境验收尚未完成。SQLite WAL 适合目前的小规模访问，但不能替代备份。材料导入限制单次 500 行，基础台账列表目前最多 500 条并采用客户端分页；测定工作台、测定记录和审计采用服务端分页，数据规模继续增长时再评估基础台账分页。
