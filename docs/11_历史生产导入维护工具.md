# 200份历史数据受控生产导入维护工具

本工具独立版本为 **1.0.0**，仅支持已验收的 SeedLab **0.5.1** 与数据库版本 **d2e7a46b910c**。它是一次性部署维护工具，未增加网页入口、修改正常业务代码、修改数据库结构或迁移，也不改变 SeedLab VERSION、tag 和已验收 portable。

## 操作步骤

1. 部署已验收的 v0.5.1 portable，选择独立、长期保存的正式数据目录。
2. 首次启动 SeedLab，初始化正式管理员。不要创建物种、批次、实验或普通导入任务。
3. 通过控制中心停止服务。确认服务停止后再运行维护工具。
4. 将独立维护 EXE 放在数据目录之外，用下面的命令只读预核验。
5. 核对预核验报告的负责人、源文件、数据目录和数量；全部通过后执行正式导入。
6. 核对正式报告及导入前、导入后备份。启动 SeedLab，查看历史实验和历史测定记录，再正式导出工作簿。

```powershell
.\SeedLabLegacyImport-v1.0.0.exe --help

# 默认只读；绝不创建数据库备份、导入任务或审计记录
.\SeedLabLegacyImport-v1.0.0.exe --source "D:\历史记录\种子发芽试验结果统计(11).xlsx" --data-root "D:\SeedLabData" --owner "实验负责人用户名" --output-dir "D:\导入核验报告"

# 同时明确指定 apply 和确认令牌才会写入
.\SeedLabLegacyImport-v1.0.0.exe --source "D:\历史记录\种子发芽试验结果统计(11).xlsx" --data-root "D:\SeedLabData" --owner "实验负责人用户名" --apply --confirm LEGACY-200-202608 --output-dir "D:\正式导入报告"
```

所有文件路径必须为绝对路径。报告目录必须独立于 Data Root，且为空；省略时在工具旁创建唯一报告目录。普通双击或缺少参数只会显示参数说明，不写数据库。对方电脑无需 Python、Node、Git、VS Code 或源码仓库。

## 固定事实与保护

源 Excel SHA-256 固定为 `1099d3074570ef83f53c03ed24ffb413848dfd256969258d24fb41d049255f3e`。源文件只读打开，导入前、提交前、导入后重复计算 SHA，不保存回源文件。人工确认的学名、置床日期映射与旧临时验证入口共用 `legacy_import_core.py`，没有第二套事实解析器。

Data Root 按正式布局识别：`data/seedlab.db`、`config/seedlab.json`、`config/instance.json`、日志及既有备份目录。安装定位文件 `config/installation.json` 实际属于 **Program Root**，不在 Data Root；维护工具不创建或改写定位文件。配置、部署标识、固定迁移版本、完整表结构契约、完整性与外键检查都必须通过。结构契约忽略 Alembic 重建表时的约束排列顺序，但比较完整列、约束、索引和表集合。

Data Root 不可靠记录 app VERSION，报告明确标注 `target compatibility: SeedLab 0.5.1 / d2e7a46b910c`；本工具所附正式导出及任务逻辑也锁定 0.5.1。未知未来版本拒绝导入，不执行迁移。TEMP、Git 仓库、开发 backend、投产验收及 legacy backfill 临时目录拒绝使用；任何重定向文件或目录也拒绝使用。

只允许已有可用管理员、所有业务表为空的数据库。负责人通过唯一、可用的用户名定位，不创建用户。users、sessions 和初始化审计事实保留；import_jobs 必须为零。重复 dry-run 和 apply 均明确拒绝非空业务库。

正式写入前检查 WAL/SHM/journal、Windows 文件共享占用、SQLite 写锁和部署监听端口。在备份、事务、提交后核验及恢复期间持续保留部署监听端口，阻止正常服务并发启动。数据库有活动连接或端口被占用时提示：**请先通过SeedLab控制中心停止服务，再执行正式历史导入。** 只读预核验使用 immutable SQLite 连接，拒绝有侧文件的数据库，避免遗漏 WAL 中尚未归并的事实。

## 事务与核账

正式写入前通过 SQLite backup API 建立 PRE-IMPORT BACKUP，验证完整性、外键、唯一文件名、size 与 SHA-256。失败时不进入导入事务。备份存放在已有 `backups/manual`，只备份 seedlab.db。

随后在 `BEGIN IMMEDIATE` 的**一个事务**中写入实验、方案、物种、批次、材料、培养皿、真实幼苗、真实测定和一条既有模式的导入审计。重新检查空库、负责人和结构，逐值反向核对数据库，调用 SeedLab 0.5.1 正式工作簿生成器并逐值反向核账，核对当前任务及外键，重新校验源 SHA。全部通过才 COMMIT；任意失败 ROLLBACK。工作簿核账在提交前完成，无“已提交但导出失败”的窗口。

提交后再次核对任务与历史查询，建立 POST-IMPORT BACKUP，并写两份报告。如果提交后的核验、备份或报告写入失败，工具用 SQLite backup API 自动恢复 PRE-IMPORT BACKUP，并重新验证空库、结构、完整性和负责人；这一恢复路径有故障注入测试。操作系统强制终止、断电或介质故障不能由进程捕获，应保留 PRE 备份和数据库交由维护人员核查。

历史实验为 `GER-202608-001`，名称“200份材料历史种子萌发试验”，状态 **completed**，`ended_at=NULL`。开始及编号锁定时间取源事实最早置床时间，计划开始日期为 2026-08-03；50 粒/皿、单重复、每皿取样 10 株、首批发芽取样，观察期限和发芽标准为空。无巡检、发芽率、干重或虚构测定。

| 核账内容 | 结果 |
|---|---:|
| 物种 / 批次 / 材料 / 已置床培养皿 | 198 / 200 / 200 / 200 |
| 真实幼苗 / 真实测定 / 测定时间点 | 1665 / 4955 / 3 |
| DAG3 / DAG7 / DAG14 | 1655 / 1655 / 1645 |
| 宽表计划幼苗 / 长表计划测定 | 2000 / 6000 |
| 已测定 / 真实幼苗缺测 / 无实际幼苗测定槽位 | 4955 / 40 / 1005 |
| 未取得幼苗计划槽位 | 335 |
| 根长真实零 / 苗长真实零 | 6 / 283 |
| 单侧缺失 / 负数 / 数据库逐值差异 / 工作簿逐值差异 | 0 / 0 / 0 / 0 |
| 当前巡检、测定、逾期、今日、后续、仪表盘任务 | 全为 0 |

DAG 是“发芽后测定时间”；每条实际测定时间严格等于实际发芽时间加 DAG。材料027保留10株真实幼苗，各DAG长度槽位为空；不误标为无实际幼苗。零保留数值0，未记录保留空白；发芽汇总为空，原始巡检表无记录；导出不含 UUID 或培养皿内部技术编号。

## 构建与开发验证

先提交维护源码，再运行 `scripts/build_legacy_importer.ps1`。构建仅使用现有 `.venv` 的 PyInstaller，输出 `dist/legacy-importer-v1/SeedLabLegacyImport-v1.0.0.exe` 和 `artifact-report.json`。报告记录源码 Git commit、size 与 SHA。EXE 内版本独立为1.0.0，固定包含 schema contract、构建 provenance、必要时区与拼音资源；安全门检查实际 PyInstaller 归档和模块目录，不打包源 Excel、数据库、SeedLabData、secrets、Git 目录或测试数据。只嵌入规定的 commit 字符串，不嵌入 .git 信息。

```powershell
$env:SEEDLAB_LEGACY_SOURCE = 'C:\Users\73971\Desktop\种子发芽试验结果统计(11).xlsx'
.\.venv\Scripts\python.exe -m pytest backend/tests/test_legacy_backfill.py backend/tests/test_legacy_production_import.py -q --basetemp "<全新一次性临时测试目录>"
```

原始工作簿集成测试由 `SEEDLAB_LEGACY_SOURCE` 显式启用，源文件不入 Git。测试仅在一次性库中执行，不形成长期测试备份；正式备份机制仅作用于不可替代的正式 seedlab.db。完整演练结果和 EXE 身份见同目录的验收记录。
