# 实验配置业务规则

## 默认方案和有效值

每个实验最多一条 `ExperimentProtocol`，保存默认每皿置床种子数、每材料重复数、计划发芽观察天数、取样规则、取样数与范围、发芽判定标准和备注。当前仅支持 `first_germinated`（按发芽顺序取前 N 株）；判定标准是实验者填写的文字，不内置固定长度阈值。

`observation_period_days` 是可选的计划参数，新建时留空（`NULL`），有值时必须为正整数，不使用 0 表示未设置。它仅用于预计日期和超期提醒，不影响方案完整性、就绪、置床或后续巡检；不会自动结束观察或实验，也不代表最终发芽率或 0 发芽。已有实验的天数保留原值，不批量清空。

`ExperimentMaterial` 表示参与实验的一个具体种子批次。同一实验不能重复加入同一批次，停用批次不能新加入。材料默认按中文名完整拼音、学名、原始材料编号、系统批次编号稳定排序；同名多批次相邻。草稿阶段预览“预计001”等编号；已就绪后确认置床编号，按服务端排序固定 `experiment_number` 并生成计划培养皿。编号确认后不可修改材料或方案；若没有培养皿实际置床，可解除确认并重新调整。材料的 `seeds_per_dish_override`、`replicate_count_override`、`sample_count_override` 为 `NULL` 时分别继承协议默认值。服务层给出三个有效数值；数值均需大于 0。

取样范围 `per_dish` 表示每个培养皿取 N 株，此时有效 N 不得超过有效每皿种子数。`per_material` 表示每个实验材料合计取 N 株，此时有效 N 不得超过有效每皿种子数乘有效重复数。更新默认方案或任一材料覆盖时重新校验所有受影响材料。

## DAG 与两套时间基准

实验的 DAG（Days After Germination）时间点为非负整数，实验内唯一，保存与读取时升序排列。创建向导预填 3、7、14 天只是可修改的界面建议；数据库和服务不以这些数字作为固定规则。测定任务将单株 `SeedlingSample.germinated_at` 转为实验室本地日期，再加 `day_after_germination` 自然日计算，其中 `germinated_at` 来自首次判定发芽的巡检。培养皿的 `sown_at` 是实际置床时间，用于巡检的置床后天数派生，与 DAG 分开。

## 动态工作量估算

设每个材料的有效重复数为 `R`、有效每皿种子数为 `S`、有效取样数为 `N`，DAG 节点数为 `D`：

- 材料数：所选材料条数。
- 预计培养皿数：`Σ R`。
- 预计置床种子数：`Σ (R × S)`。
- 预计幼苗取样数：每皿取样为 `Σ (R × N)`；每材料取样为 `Σ N`。
- 预计根苗长测定记录数：预计样本数 `× D`。
- 后台暂保留预计最晚完成日期字段，仅当计划开始日期、计划发芽观察天数和 DAG 均存在时，按计划开始日期 + 计划观察天数 + 最大 DAG 计算；缺少任一项返回 `NULL`，不补默认观察期限。该公式假设所有材料在计划日置床，无法反映分批置床和每日处理能力，因此不在主要用户界面展示。

估算按当前配置即时计算，不冗余保存。Stage 1 的原始交付只保存实验设计；当前草稿和未确认编号的已就绪实验可以修改设计。确认编号后必须先在尚未置床时解除确认，才能修改；`active`、`completed`、`cancelled` 禁止结构性配置变化。

当前工作流在确认编号事务中生成全部计划培养皿，此时没有实际置床时间，实验仍为 `ready`；第一批真实置床在同一事务内使实验变为 `active`，并以最早实际置床时间作为开始时间。执行后编号及培养皿不再随配置变化；规则见 [发芽实验执行业务规则](06_发芽实验执行业务规则.md)。
