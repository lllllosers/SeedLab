# 实验配置业务规则

## 默认方案和有效值

每个实验最多一条 `ExperimentProtocol`，保存默认每皿置床种子数、每材料重复数、计划发芽观察天数、取样规则、取样数与范围、发芽判定标准和备注。当前仅支持 `first_germinated`（按发芽顺序取前 N 株）；判定标准是实验者填写的文字，不内置固定长度阈值。

`observation_period_days` 是可选的计划参数，新建时留空（`NULL`），有值时必须为正整数，不使用 0 表示未设置。它仅用于预计日期和超期提醒，不影响方案完整性、就绪、置床或后续巡检；不会自动结束观察或实验，也不代表最终发芽率或 0 发芽。已有实验的天数保留原值，不批量清空。

`ExperimentMaterial` 表示参与实验的一个具体种子批次。同一实验不能重复加入同一批次，停用批次不能新加入。材料默认按中文名完整拼音、学名、原始材料编号、系统批次编号稳定排序；同名多批次相邻。草稿阶段预览“预计001”等编号；已就绪后确认置床编号，按服务端排序固定 `experiment_number` 并生成计划培养皿。编号确认后不可修改材料或方案；若没有培养皿实际置床，可解除确认并重新调整。材料的 `seeds_per_dish_override`、`replicate_count_override`、`sample_count_override` 为 `NULL` 时分别继承协议默认值。服务层给出三个有效数值；数值均需大于 0。

取样范围 `per_dish` 表示每个培养皿取 N 株，此时有效 N 不得超过有效每皿种子数。`per_material` 表示每个实验材料合计取 N 株，此时有效 N 不得超过有效每皿种子数乘有效重复数。更新默认方案或任一材料覆盖时重新校验所有受影响材料。

## DAG 与两套时间基准

实验的 DAG（Days After Germination）时间点为非负整数，实验内唯一，保存与读取时升序排列。创建向导预填 3、7、14 天只是可修改的界面建议；数据库和服务不以这些数字作为固定规则。测定任务将单株 `SeedlingSample.germinated_at` 转为实验室本地日期，再加 `day_after_germination` 自然日计算，其中 `germinated_at` 来自首次判定发芽的巡检。培养皿的 `sown_at` 是实际置床时间，用于巡检的置床后天数派生，与 DAG 分开。

## 动态工作量估算

设每个材料的有效重复数为 `R`、有效每皿种子数为 `S`、有效取样数为 `N`，DAG 节点数为 `D`：

- 材料数：所选材料条数。
- 预计培养皿数：`Σ R`。
- 预计置床种子数：`Σ (R × S)`。
- 预计幼苗取样数：每皿取样为 `Σ (R × N)`；每材料取样为 `Σ N`。
- 预计根苗长测定记录数：预计样本数 `× D`。
- 后台暂保留预计最晚完成日期字段，仅当计划开始日期、计划发芽观察天数和 DAG 均存在时，按计划开始日期 + 计划观察天数 + 最大 DAG 计算；缺少任一项返回 `NULL`，不补默认观察期限。该公式假设所有材料在计划日置床，无法反映分批置床和每日处理能力，因此不在主要用户界面展示。

估算按当前配置即时计算，不冗余保存。Stage 1 的原始交付只保存实验设计；当前草稿和未确认编号的已就绪实验可以修改设计。确认编号后必须先在尚未置床时解除确认，才能修改；`active`、`completed`、`cancelled` 禁止结构性配置变化。

当前工作流在确认编号事务中生成全部计划培养皿，此时没有实际置床时间，实验仍为 `ready`；第一批真实置床在同一事务内使实验变为 `active`，并以最早实际置床时间作为开始时间。执行后编号及培养皿不再随配置变化；规则见 [发芽实验执行业务规则](06_发芽实验执行业务规则.md)。

## AF-3 实现职责

实验身份与正式状态转换属于 Experiment Core；GER 默认方案、覆盖值、DAG、方案可编辑条件和就绪判断由 germination_config / germination_workflow 负责。Core 通过当前静态 GER workflow 执行就绪校验后写状态，不直接查询 GER 方案或培养皿。原 HTTP 校验顺序、业务提示、材料排序、配置快照及事务保持；通用材料参与关系和 GER 覆盖值仍共用原 ExperimentMaterial 表。

## 材料清单身份审查

v0.6.1 将物种、种子材料和两级萌发试验历史分别展示。保留“完整 / 更新清单”和“仅新增材料清单”，模式只影响材料判断倾向，不影响物种身份。科学名比较键位于 material_import.scientific_comparison_key：NFKC、下划线转空格、Unicode 空白折叠并 trim、casefold；只用于比较，不批量改写或规范化已保存学名。中文名仅 NFKC 和空白规范化，保留括号、编号及后缀，不做模糊匹配或同义名推断。

物种优先按有效 SP 编号匹配，编号与学名冲突阻断；其次按科学名比较键 exact 匹配。中文名不同默认沿用系统名称；仅在学名已确认相同的已有物种上，允许明确选择更新中文名，随最终导入一起提交并记录审计。只修改 common_name，不改学名、Taxon ID、SeedLot、ExperimentMaterial 或历史事实，不新增 alias 表。预检和选择本身不写库；同一物种选择多个不同的新名称会阻止整份导入。学名未匹配但中文名 exact 匹配时必须选择已有物种或确认为新物种，缺学名不能新建。科学名比较键碰撞返回全部候选，不能静默挑选或重复新建。二者均未匹配才作为数据库中新物种候选。

物种确定后，原始材料编号在该物种下唯一匹配可复用；来源和日期强匹配沿用现有规则。来源不同可建立新材料；缺稳定编号且多份材料不能唯一确定时，独立选择已有批次或另一份新材料。单有物种相同不复用材料，停用历史材料仍参与候选核对。确认导入服务端重做预检，候选失效、未决身份或文件错误阻止整份导入；新增材料只绑定已解析的物种，事务失败全部回滚。

历史通过 Taxon ID → SeedLot → ExperimentMaterial → GER Experiment，及 SeedLot ID → ExperimentMaterial → GER Experiment 查询，不重新比较名称。历史试验列分别显示物种、本材料：completed 为“做过”，active 为“正在做”，draft / ready / cancelled 为“有历史记录”，none 为“没做过”；身份未定为“待确认后核对”。身份状态使用文字和符号区分“✓ 历史已有 / ＋ 本次新增 / ! 待确认”及对应材料状态，空字段补全与资料差异另列。Excel 行号和系统编号只作辅助定位。

顶部“本次实验筛选”使用预检 facts 动态投影，不改变身份匹配算法：只做历史没做过的物种，按已解析 Taxon ID 或规范化新学名去重；同物种不同来源也单独做，已有材料按批次 ID、候选材料按物种及来源/采集日期分组，原始材料编号存在时优先作为强身份。明确保留为不同材料的重复行分别计入；合并清单材料跟随被合并行。相同来源且没有稳定编号的历史关联候选默认不当作明确新批次，明确选择另一份新材料后再计入。待确认物种不偷计入新增或已有；待确认材料单独显示，选择后重做预检并更新数量。两个方案按钮仅展示每组代表记录，同时说明同组清单条数。

识别行数保留在“查看识别明细”折叠区，并说明不是最终实验数量。搜索支持中文名、学名、来源及原始材料编号；快速筛选包括全部、待确认、新增物种、历史已有物种、新材料及历史试验记录。顶部“立即处理”集中展示未决项，全部处理后才能确认导入。候选卡直接展示物种、来源、原始编号、日期及历史；清单内部重复展示另一条完整材料信息，按钮为“合并为同一份材料 / 保留为两份不同材料”。物种核对展示新表与系统学名对照，不自动判断分类同义名。

合成生产反馈及事务回归见[身份测试](../backend/tests/test_material_identity_review.py)与[筛选及名称测试](../backend/tests/test_material_review_selection.py)。真实 303 清单不作为 Git fixture，143/159/1、156 个物种及 192 份材料是下一轮 Mirror 复核基线，不是代码常量；本轮合成自动门不冒充真实清单人工 UX 验收。
