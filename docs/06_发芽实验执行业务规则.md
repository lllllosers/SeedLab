# 发芽实验执行业务规则

## 编号确认、置床与培养皿

只有配置完整的 `ready` 实验可以确认置床编号。一次数据库事务按中文名完整拼音、学名、原始材料编号、系统批次编号排序，为每个实验材料固定从 001 开始的编号，按各材料的有效每皿粒数和重复数生成 `sown_at` 为空的计划培养皿，记录编号确认时间和审计。单重复培养皿现场编号为 001，多重复为 001-1、001-2 等。培养皿 UUID 是数据库身份；`EXP-…-M001-R01` 一类内部编号保持稳定用于追溯。尚无任何培养皿实际置床时，可解除编号确认、删除计划皿并回到草稿；已置床后不得重排或补号。未解除确认的已取消皿仍保留原现场编号。

一个或多个未置床培养皿可在任意日期批量登记同一实际置床时间；每皿均有独立 `sown_at`。第一次登记使实验从 `ready` 变为 `active`，`started_at` 取最早真实置床时间，全部在同一事务完成。后续可非连续、分多日继续置床，编号不变。未置床皿可说明原因后取消，取消皿不得置床或巡检。已置床皿可纠正置床时间，但不能晚于它最早的巡检时间。普通 PATCH 不能直接完成 `ready → active`。

`SeedLot.quantity` 是资料字段。置床登记不扣减数量，数量未填写也不阻止置床。确认编号后不重新生成或改变培养皿数。

## 巡检事实与动态汇总

每条 `GerminationObservation` 保存一个培养皿的完整 `observed_at`、本次新增 `new_germinated_count` 和备注。同一天允许多次巡检。批量表单留空的培养皿不创建记录；明确填写 `0` 会创建一条“已巡检但本次无新增”的事实记录。累计发芽数是该皿所有新增数之和，发芽率为累计数除以置床粒数；剩余未发芽数和材料汇总也动态派生，不存冗余列。

一批巡检共享一个 `observed_at`；允许只填写部分培养皿并保存，其他皿继续保持今日待巡检。巡检时间不得早于该皿置床时间；未置床或已取消的皿不能巡检；新增数非负；累计不能超过置床粒数；同一皿同一完整时间不可重复。今日已巡检的皿仍可在“全部已置床”中再次巡检。计划观察周期仅用于进度与超期提示，超期仍可录入真实发芽。只有 `active` 可新增巡检，系统不会因观察期届满自动完成实验。

## 前 N 株取样

当前取样规则是 `first_germinated`。新样本的 `germinated_at` 等于来源巡检的 `observed_at`，意思是“首次在巡检中判定该幼苗已经发芽的时间”，并不是系统知道真实生理发芽瞬间。`source_observation_id` 指明首次识别并选入样本的巡检；`position_label` 可空，当前不限制位置格式。`sample_number` 在培养皿内递增编号。

- `per_dish`：每个培养皿独立选择前 N 株。一次新增超过剩余名额时，仅剩余名额数量生成样本；其余仍计入发芽累计。
- `per_material`：同一材料的所有重复合计选择前 N 株。统一按巡检 `observed_at`、再按培养皿 `replicate_no` 升序选择；同一巡检内按新增幼苗的自然序号处理。同时间 R1 优先于 R2 是稳定的技术排序，不代表生物学先后差异。

巡检、样本生成和审计同事务提交。达到 N 后仍持续记录后续发芽。为保留已选实体，补录或纠错若会挤占既有前 N 株样本，服务会拒绝该操作。

## 纠错与后续边界

可修正巡检备注和本次新增数。修正后累计仍不得超过置床粒数；本次新增不能小于该巡检已产生的样本数。系统重新核对前 N 株分配，必要时可为尚有名额的已记录巡检补齐样本，但绝不静默删除或重新指派已有样本。有来源样本的巡检不能删除；无来源样本的巡检可删除。创建、修正、删除均写审计日志。

Stage 2 只覆盖发芽执行和选样。根苗长录入、DAG 今日测定任务、测量统计与异常值审核留待 Stage 3 及以后。
