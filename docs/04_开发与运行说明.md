# 开发与运行说明

## 前提

Windows、Python 3.12+、Node.js 20+、npm、Git。以下命令从仓库根目录执行。首次安装：

```powershell
# 先在终端进入仓库根目录
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e './backend[test]'
cd frontend
npm install
cd ..
Copy-Item .env.example .env
```

可在 `.env` 中设置 `SEEDLAB_ENV`（`development` / `production`）、`SEEDLAB_DATABASE_URL`、`SEEDLAB_BOOTSTRAP_TOKEN_PATH`、`SEEDLAB_SESSION_HOURS`、`SEEDLAB_COOKIE_SECURE`、`SEEDLAB_WEB_ROOT`、`SEEDLAB_TIMEZONE`（默认 Asia/Shanghai）。`.env`、SQLite、上传、日志、备份、虚拟环境和构建产物都不会进入 Git。默认初始化码文件为 `backend/data/bootstrap.token`，`data/` 已被忽略。

## 数据库与首次管理员

```powershell
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m alembic current
cd ..
.\run_dev.bat
```

数据库无用户时，首次启动的服务器本机终端会显示随机一次性 Bootstrap Token。浏览器访问 `/setup` 并使用该码创建首位管理员，成功后直接进入工作台；初始化入口随即关闭。没有预设账号或密码，也不允许公开注册。服务器本机仍可在 `backend` 目录执行 `..\.venv\Scripts\python.exe -m app.cli create-admin admin --name "管理员"` 作为应急或维护入口；CLI 交互输入 8 至 128 位密码。执行迁移前不应启动 API；应用不调用 `create_all`。

当前正式 v0.5.1 Alembic head 为 `d2e7a46b910c`，接续 v0.4.1 基线 `c6d91f28a405`；所有历史迁移保留。以上原始 Alembic 命令仅用于开发初始化和显式临时库验证；生产启动和部署复用必须经共享升级协调入口，不能用裸 `alembic upgrade head` 绕过升级前备份。检查采用 `alembic current`、`alembic heads` 与 `alembic check`。迁移往返仅在系统临时数据库上验证；测试覆盖已存在数据、回退保护和再次升级。不要对当前人工测试库直接回退，NA、备注或终止原因等事实可能阻止安全降级。完整升级与显式恢复操作见[生产运维](10_生产部署与控制中心设计.md)。

## 启动与检查

在仓库根目录运行 `run_dev.bat`。脚本检查依赖、执行迁移并在同一个终端启动 API 和 Vite；Ctrl+C 停止。访问 <http://localhost:5173>，API 健康检查 <http://localhost:8000/api/health>，开发文档 <http://localhost:8000/docs>。

运行 `run_tests.bat`（后端全量 pytest），在 `frontend` 目录执行 `npm test` 和 `npm run build`（TypeScript 检查 + Vite 构建）。正式测试使用 `tmp_path` 和系统临时目录，不向项目数据目录写测试库。

项目卫生使用 `scripts/project_hygiene_check.ps1` 只读诊断；缓存清理先执行 `scripts/clean_dev_artifacts.ps1 -DryRun`。开发重置与备份保留策略详见[人工测试与开发数据重置](09_人工测试与开发数据重置.md)，三个工具职责独立。

## 局域网与安全

开发脚本监听所有网卡，供局域网浏览器访问。生产 runner 默认只监听本机，可显式指定 `--host 0.0.0.0` 测试局域网访问。本机/可信局域网 HTTP 使用 `SEEDLAB_COOKIE_SECURE=false`；在可信代理后通过 HTTPS 提供同源页面和 API 时设为 true，并限制访问来源。production 不强制修改 Cookie 配置。若使用公网穿透，应先配置 HTTPS 与访问控制，不要直接暴露开发服务器。SQLite 数据库及其 WAL/SHM 文件需要一致性备份；不要在运行中直接复制单个 `.db` 文件当作可靠备份。

## 源码生产入口验证

源码生产运行先构建再启动；`run_dev.bat` 继续用于开发。v0.4.1 已提供 Control Center 和便携部署包，详见[生产部署与控制中心设计](10_生产部署与控制中心设计.md)及[打包说明](../packaging/README.md)。以下脚本用于开发者验证单端口生产入口。

```powershell
# 已安装前端依赖后，任选脚本或直接 npm run build
.\scripts\build_production.ps1
# 等价：cd frontend; npm run build; cd ..
.\run_prod.bat
```

访问 <http://127.0.0.1:8848>，健康检查为 <http://127.0.0.1:8848/api/health>。AF-1 源码生产启动强制 `SEEDLAB_ENV=production`，检查前端文件后执行数据库兼容性判断与升级准备；只有必要的旧库迁移才建立升级前快照，任何检查失败都停止。单端口同时提供页面与 API，关闭 `/docs`，不启动 Vite，也不需要 Node.js 常驻或 node_modules。Ctrl+C 停止。

```powershell
.\.venv\Scripts\python.exe scripts/run_prod.py --host 0.0.0.0 --port 8848
.\.venv\Scripts\python.exe scripts/run_prod.py --web-root .\frontend\dist
```

`SEEDLAB_WEB_ROOT` 默认 `frontend/dist`，支持绝对路径；相对路径以项目根目录为基准。`--web-root` 覆盖配置。缺少 `index.html` 时需先构建或修正路径，开发环境无 dist 仍可启动。数据库及初始化码相对路径继续以 backend 为基准，与开发启动一致。自动测试请显式设置隔离数据库与初始化码路径，不要重置当前人工测试库。

Vue 页面可直接输入地址并刷新；未知 API 和缺失资源仍返回 404。另一设备访问局域网主机 IP 需要网络允许；脚本不修改 Windows 防火墙。后续部署规划见[生产部署与控制中心设计](10_生产部署与控制中心设计.md)。

## API 概览

| 范围 | 路径 |
| --- | --- |
| 状态 | `GET /api/health` |
| 首次初始化 | `GET /api/setup/status`、`POST /api/setup/bootstrap`（仅数据库无用户且持有本机初始化码） |
| 认证 | `POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`、`POST /api/auth/change-password` |
| 物种 | `GET/POST /api/taxa`、`GET/PATCH/DELETE /api/taxa/{id}` |
| 种子批次 | `GET/POST /api/seed-lots`、`GET/PATCH/DELETE /api/seed-lots/{id}` |
| 实验基础 | `GET/POST /api/experiments`、`GET/PATCH/DELETE /api/experiments/{id}` |
| 实验类型 | `GET /api/experiments/types` |
| 实验创建与估算 | `POST /api/experiments/configured`、`POST /api/experiments/estimate` |
| 实验配置 | `GET /api/experiments/{id}/configuration`、`GET /api/experiments/{id}/workload`、`PUT /api/experiments/{id}/protocol` |
| 实验材料 | `GET /api/experiments/available-seed-lots`、`POST /api/experiments/{id}/materials`、`PATCH/DELETE /api/experiments/{id}/materials/{material_id}`；材料按中文名自动排序 |
| DAG | `PUT/POST /api/experiments/{id}/dag`、`DELETE /api/experiments/{id}/dag/{day}` |
| 置床编号与管理 | `POST /api/experiments/{id}/confirm-numbers`、`POST /api/experiments/{id}/reopen-design`、`GET /api/experiments/{id}/sowing-sheet.xlsx`、`POST /api/experiments/{id}/sowing/batch`、`PATCH /api/experiments/{id}/sowing/{dish_id}`、`POST /api/experiments/{id}/sowing/{dish_id}/cancel` |
| 发芽执行 | `GET /api/experiments/{id}/execution`、`GET /api/experiments/{id}/samples` |
| 发芽巡检 | `POST /api/experiments/{id}/observations/batch`、`POST /api/experiments/{id}/observations`、`PATCH/DELETE /api/experiments/{id}/observations/{observation_id}` |
| 幼苗测定 | `GET /api/experiments/{id}/measurement-worklist`、`GET /api/experiments/{id}/measurement-tasks`、`GET /api/experiments/{id}/measurement-records`、`POST /api/experiments/{id}/measurements`、`PATCH/DELETE /api/experiments/{id}/measurements/{measurement_id}` |
| 实验结束 | `GET /api/experiments/{id}/completion-check`、`POST /api/experiments/{id}/complete`、`POST /api/experiments/{id}/terminate` |
| 工作台 | `GET /api/dashboard` |
| 系统 | `GET /api/audit-logs`、`GET/POST /api/users`、`PATCH /api/users/{id}`、`POST /api/users/{id}/reset-password`（用户管理仅管理员） |
| 数据交换 | `GET /api/export/materials-template.xlsx`、`POST /api/import/materials/preview`、`POST /api/import/materials/confirm`、`POST /api/export/experiments/workbook.xlsx`、`GET /api/export/catalog.xlsx` |

登录以外的业务 API 需要会话；POST/PUT/PATCH/DELETE 附带登录或 /auth/me 返回的 X-CSRF-Token。输入、权限和业务状态以当前 contracts（Auth/Catalog 仍使用 API schema）、代码与回归测试为准。账号规则见[07](07_账号初始化与权限管理.md)，实验配置见[05](05_实验配置业务规则.md)，置床与巡检见[06](06_发芽实验执行业务规则.md)，测定与生命周期见[08](08_幼苗测定业务规则.md)。

Vue Router 是前端页面路由唯一来源；实验创建为 /experiments/new，配置详情为 /experiments/:id，GER 执行及测定为 /experiments/:id/germination。当前这些通用实验页面包含 GER 业务假设，AF-4 不迁移前端目录或改路由。

## 完整质量门

从仓库根目录使用已有测试入口；系统临时库由测试创建和清理，不读取或修改真实 Production Data Root。固定历史源通过 SEEDLAB_LEGACY_SOURCE 只读启用，源 SHA 和启用方式见[科研数据契约](14_历史数据与导出回归契约.md#自动测试)。未提供源文件时必须单独报告相关集成测试 SKIP。

~~~powershell
.\.venv\Scripts\python.exe scripts\run_tests.py --tb=short -rs
.\.venv\Scripts\python.exe -m pip check
Set-Location frontend
npm test
npm exec vue-tsc -- --noEmit
npm run build
npm ls --depth=0
Set-Location ..\backend
..\.venv\Scripts\python.exe -m alembic heads
Set-Location ..
git diff --check
~~~

全量 pytest 已包括迁移往返、schema check、维护工具、服务器/portable、历史与长宽表回归。AF-2 新增 test_architecture_dependencies.py（显式增长域及 contracts 的 AST 导入规则，包含违规导入注入验证）和 test_growth_contracts.py（同一 DTO 身份、选择性 OpenAPI、HTTP 错误与真实业务写入回归）。AF-3 扩充架构测试以保护 Core → GER 依赖和正式生命周期写入，新增 test_experiment_registry.py 与 test_lifecycle_authority.py；包含首次/后续置床、入口时间串及审计差异、GER 清理失败的事务回滚。AF-4 新增 test_measurement_dataset.py，保护脱离 ORM 的只读契约、无 autoflush 与工作簿改动前内容摘要；扩充架构测试保护 Analysis 依赖及投影无写入，DAG parity 同时比较 dataset、Python 与 SQL，覆盖闰日等日期边界。历史 200 回归同时核账中立 dataset 的 2000/6000 计划槽位与 1665/4955/40 实际事实。新增增长服务或 DTO 时应同步维护这些断言；Auth/Control Center/CLI 不在增长服务名单中。AF-1 的 test_database_upgrade_recovery.py 另覆盖当前库反复启动、旧库完整升级顺序、各阶段失败阻断、故障现场保留、跨进程占用和显式恢复。所有升级/恢复文件只写到测试临时目录。数据库 current/check、integrity_check 和 foreign_key_check 必须针对测试显式创建的临时目标执行；不要为了检查而打开默认开发库或生产库。代表性历史库检查也在 test_legacy_backfill.py 的 temporary_target 上完成。没有真实生产副本时报告 production clone smoke unavailable，不以临时库冒充生产副本。

质量门必须记录实际 passed/skipped 数量和每个跳过项的 node ID、原因，不能笼统报告“全部通过”。未设置 SEEDLAB_LEGACY_SOURCE 会跳过五个固定历史源集成用例；Windows 账号没有创建符号链接的权限时会跳过一个重定向防护用例。启用经过 SHA 核验的原始历史源后须实际执行这五项，而不是把 skip 计入通过。既有 Starlette 测试客户端弃用提示只记录，不为消除提示升级 FastAPI/httpx 或改变依赖。

对 Git 跟踪及本阶段新增的 Python 源文件做 AST parse，以及在显式内存数据库环境下导入 app / control_center 模块，作为语法和导入检查；不能启动 CLI、服务或 Qt 窗口来做导入验证。项目当前未配置 ruff / mypy 门，不在 AF-4 安装新工具或改规则。

已有 portable 只读门可检查目录及 ZIP，按下面固定目标调用；不会重建 EXE/ZIP，也不启动正式部署：

~~~powershell
.\.venv\Scripts\python.exe scripts\check_portable.py --directory .\dist\portable-v051\SeedLab --zip .\dist\portable-v051\SeedLab-v0.5.1-portable.zip
~~~

完成后检查文档本地链接、删除路径引用、个人绝对路径、意外数据库、临时文件、缓存和生成物。清理只能使用核对后的明确范围；正式分发和生产数据边界见[09](09_人工测试与开发数据重置.md)及[10](10_生产部署与控制中心设计.md)。测试证据属于当前执行报告，不另建长期日志或源码备份。
