# 开发与运行说明

## 前提

Windows、Python 3.12+、Node.js 20+、npm、Git。项目目录为 `E:\gitProject\SeedLab`。首次安装：

```powershell
cd E:\gitProject\SeedLab
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e './backend[test]'
cd frontend
npm install
cd ..
Copy-Item .env.example .env
```

可在 `.env` 中设置 `SEEDLAB_ENV`（`development` / `production`）、`SEEDLAB_DATABASE_URL`、`SEEDLAB_BOOTSTRAP_TOKEN_PATH`、`SEEDLAB_SESSION_HOURS`、`SEEDLAB_COOKIE_SECURE`。`.env`、SQLite、上传、日志、备份、虚拟环境和构建产物都不会进入 Git。默认初始化码文件为 `backend/data/bootstrap.token`，`data/` 已被忽略。

## 数据库与首次管理员

```powershell
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m alembic current
cd ..
.\run_dev.bat
```

数据库无用户时，首次启动的服务器本机终端会显示随机一次性 Bootstrap Token。浏览器访问 `/setup` 并使用该码创建首位管理员，成功后直接进入工作台；初始化入口随即关闭。没有预设账号或密码，也不允许公开注册。服务器本机仍可在 `backend` 目录执行 `..\.venv\Scripts\python.exe -m app.cli create-admin admin --name "管理员"` 作为应急或维护入口；CLI 交互输入 8 至 128 位密码。执行迁移前不应启动 API；应用不调用 `create_all`。

当前开发分支 Alembic head 为 `e8b62c74a901`，上一版本为 `a9c41e32b7d6`。升级采用 `alembic upgrade head`。若需验证本轮迁移往返，应在测试数据库上执行 `alembic downgrade a9c41e32b7d6`，再执行 `alembic upgrade head`、`alembic check` 和 SQLite `PRAGMA foreign_key_check`。回退会移除本轮新增字段，不要直接对真实数据执行。

## 启动与检查

在仓库根目录运行 `run_dev.bat`。脚本检查依赖、执行迁移并在同一个终端启动 API 和 Vite；Ctrl+C 停止。访问 <http://localhost:5173>，API 健康检查 <http://localhost:8000/api/health>，开发文档 <http://localhost:8000/docs>。

运行 `run_tests.bat`（pytest）和 `cd frontend; npm run build`（TypeScript 检查 + Vite 构建）。

## 局域网与安全

开发脚本监听所有网卡，供局域网浏览器访问。生产环境应在可信代理后通过 HTTPS 提供同源页面和 API，设置 `SEEDLAB_ENV=production` 与 `SEEDLAB_COOKIE_SECURE=true`，并限制访问来源。开发脚本不等于生产部署。若使用公网穿透，应先配置 HTTPS 与访问控制，不要直接暴露开发服务器。SQLite 数据库及其 WAL/SHM 文件需要一致性备份；不要在运行中直接复制单个 `.db` 文件当作可靠备份。

登录以外的业务 API 需要会话。POST/PATCH/DELETE 必须附带登录或 `/auth/me` 返回的 `X-CSRF-Token`。持临时密码登录的用户只能访问 `/auth/me`、改密和退出；改密、管理员重置密码或停用账号都会清除相关会话。详细规则见[账号初始化与权限管理](07_账号初始化与权限管理.md)。物种导入可在页面下载模板，使用首行含“学名”的 `.xlsx`，可选“中文名”“科”。导入最多 500 行、2 MB，学名重复整批拒绝。

种子批次导入：在前端“导入与导出”下载 `.xlsx` 模板，模板预填当前启用物种的“物种编号”“中文名”“学名”。填写“来源”“数量”“备注”后上传；只按“物种编号”匹配，名称供人工核对。不存在或已停用的物种、负数或非整数数量均报具体行号。数量可空；单次最多 500 行、5 MB。所有行先验证，出错时整表不写入；成功后每行新建 SeedLot，并写 ImportJob 与 AuditLog。SeedLot 通过 UUID 关联物种；`LOT-YYYY-NNN` 仍是用户可见编号，正式编号规则在 v1.0 前确定。

幼苗根苗长时间点采用 DAG（Days After Germination）：`MeasurementTimepoint.day_after_germination` 为实验内唯一的非负天数；未来计划按单株 `SeedlingSample.germinated_at` 计算。`GerminationDish.sown_at` 仍表示培养皿置床时间，若巡检需要置床后天数，应由它派生。

创建实验使用 `/experiments/new` 七步向导。默认方案、材料覆盖、两种取样范围与工作量计算详见 [实验配置业务规则](05_实验配置业务规则.md)。实验处于 `draft` / `ready` 时可以调整结构；`active` 与终态仅允许编辑普通说明等基础信息。

`ready` 实验先确认置床编号并生成未置床的计划培养皿；首次登记真实置床时间后自动进入 `active` 并可在 `/experiments/{id}/germination` 巡检。普通 PATCH 无法直接进入 `active`。同一批量巡检共享一个 `observed_at`，留空的培养皿不创建记录，明确填写 `0` 会创建本次新增为 0 的记录；API 时间须携带时区。更多校验与纠错规则见 [发芽实验执行业务规则](06_发芽实验执行业务规则.md)。

一体导入使用 12 列中文模板，每次最多 500 行；预检只读，确认后整批写库。完整清单模式下，缺少原始材料编号但仅有一个可用批次且来源、日期不冲突时自动复用；多候选或冲突时支持逐条与批量确认。本次新增模式倾向新建批次，明显重复的材料需确认。材料顺序以服务端中文名完整拼音排序为准，编号确认后不因置床先后而变化。联合导出使用同一服务处理单实验或多实验，生成六张中文工作表；发芽率汇总只计算实际已置床培养皿，无实际置床种子时留空。汇总编号只属于当次导出。详见 [核心数据模型](02_核心数据模型.md) 和 [实验配置业务规则](05_实验配置业务规则.md)。
