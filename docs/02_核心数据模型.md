# 核心数据模型

首次迁移：`3179cf93a5f4_initial_schema.py`；DAG 修复：`9456099da4fd_align_germination_based_dag.py`；Stage 1：`d50447b51d78_stage1_experiment_configuration.py`；Stage 2：`f705a6bb943c_add_germination_execution_provenance.py`；账号初始化：`a9c41e32b7d6_add_initial_password_change_flag.py`；当前开发分支 head：`e8b62c74a901_manual_workflow_round2.py`。13 个约定业务实体，加一张 `sessions` 会话表。

| 实体 | 核心字段 | 关系或约束 |
| --- | --- | --- |
| User | username、password_hash、is_admin、is_active、must_change_password | 用户名唯一；密码 Argon2；历史用户默认不强制改密，新建成员默认强制 |
| Taxon | code、scientific_name、common_name、family、genus、life_form、is_active | 编号与学名唯一；一对多 SeedLot；属与生活型可空 |
| SeedLot | code、taxon_id、source_code、source、collected_at、quantity | Taxon 外键；原始材料编号、采集/获得日期可空；数量可缺失或 ≥ 0 |
| Experiment | code、name、status、planned_start_date、numbering_locked_at、owner_id、started_at、ended_at | 草稿/就绪/进行中/完成/取消；编号确认时间可空 |
| ExperimentProtocol | experiment_id、summary、seeds_per_dish、replicate_count、observation_period_days、sampling_rule、sample_count、sample_scope、germination_criterion | 每实验至多一条；配置数值 > 0；旧数据字段可空 |
| ExperimentMaterial | experiment_id、seed_lot_id、experiment_number、label、display_order、seeds_per_dish_override、replicate_count_override、sample_count_override | 实验和种子批次组合唯一；本次实验编号可空、正数且实验内唯一；覆盖值可空且非空时 > 0 |
| MeasurementTimepoint | experiment_id、day_after_germination、label | DAG 为非负整数；同一实验内唯一 |
| GerminationDish | material_id、code、replicate_no、label、seed_count、sown_at、cancelled_at、cancel_reason | code 全局唯一；材料内重复号及标签唯一；重复号与粒数 > 0；实际置床与取消不可同时存在 |
| GerminationObservation | dish_id、observed_at、new_germinated_count、notes | 培养皿和时间唯一；新增数 ≥ 0 |
| SeedlingSample | dish_id、sample_number、germinated_at、source_observation_id、position_label | 培养皿内样本号唯一；来源巡检可追踪；历史行允许缺失 |
| SeedlingMeasurement | sample_id、timepoint_id、root_length_mm、shoot_length_mm | 样本和时间点唯一；长度可为 0 或 NULL |
| AuditLog | user_id、action、entity_type、entity_id、before、after | 重要数据变更留痕 |
| ImportJob | user_id、filename、file_hash、status、行数 | 导入结果；成功一体导入文件的 SHA-256 唯一 |
| SessionToken | user_id、token_hash、csrf_token、expires_at | HttpOnly Cookie 对应的服务器会话 |

主链为 `Taxon → SeedLot → ExperimentMaterial → GerminationDish → GerminationObservation`；另一支为 `GerminationDish → SeedlingSample → SeedlingMeasurement`。`Experiment` 拥有 `ExperimentProtocol`、`MeasurementTimepoint`、`ExperimentMaterial`。

**原始事实原则：** 巡检记录仅存本次新增发芽数与完整观测时间，不存累计数、发芽率或置床后天数。数值 0 表示已巡检且本次没有新增；无记录表示没有巡检。根苗长按“样本 + 时间点”长表保存，DAG 节点动态配置，没有 `root_3d` 一类列。Stage 2 开放巡检，不开放根苗长测量 API。

**两套时间基准：** 幼苗根苗长计划采用 DAG（Days After Germination），即单株幼苗被判定发芽后的第 N 天；未来以 `germinated_at + day_after_germination` 计算该株测定任务。`germinated_at` 等于来源巡检的 `observed_at`，表示首次在巡检中判定该幼苗发芽的时间，不表示生理发芽瞬间。历史样本可为 `NULL`；新选样本记录 `source_observation_id`，并保证来源巡检属于同一培养皿。培养皿的 `sown_at` 是实际置床时间；巡检需要的置床后天数可由它派生，与 DAG 不混用。

`ExperimentProtocol` 是实验默认方案；材料三个 `override` 字段为 `NULL` 时继承默认参数。有效值与工作量在服务层动态计算，详情见 [实验配置业务规则](05_实验配置业务规则.md)。当前工作流在确认置床编号时生成尚未置床的计划培养皿；第一次真实置床时实验进入 `active`，`started_at` 取最早实际置床时间。累计、发芽率和观察进度不冗余存库。

**四类编号：** 物种 `SP-xxxx` 与批次 `LOT-YYYY-NNN` 是持久身份；批次可另存来自原表的 `source_code`。`ExperimentMaterial.experiment_number` 是每个实验内独立的现场顺序编号（展示为 001）；培养皿现场编号由它与重复号派生（单重复 001，多重复 001-1）。联合导出的汇总编号只在工作簿内按所选材料重新排序生成，绝不回写。

SQLite 开启外键、30 秒 busy timeout 和 WAL。所有结构变更经 Alembic。删除已被下游引用的记录由外键拒绝；工作台、编辑页面主要使用停用状态保留履历。
