# 开发路线图

## Stage 0 — Foundation（已完成）

- 13 个核心实体、UUID 与首版 Alembic 迁移。
- 登录、管理员初始化、简单权限和审计基础。
- 工作台、物种信息库、种子批次、实验列表与基础详情。
- 物种 Excel 导入、CSV 导出，自动化测试与 Windows 开发入口。
- 收口幼苗测定时间语义：DAG 节点按发芽后天数定义，样本预留发芽判定时间字段。
- 已完成基础数据与 DAG 语义修复，作为 Stage 1 开发基线。

## Stage 1 — 实验配置（已发布，v0.2.0）

围绕 Experiment、ExperimentProtocol、ExperimentMaterial 和 MeasurementTimepoint 实现七步实验创建向导、默认参数与材料覆盖、动态 DAG、取样容量校验、工作量估算及可编辑详情。后续测定任务以单株 `germinated_at` 为基准计算。本阶段不生成培养皿、样本或任务。

## Stage 2 — Germination Execution（已发布，v0.3.0）

在 Stage 1 实验配置基础上，从 `ready` 原子启动实验、生成带稳定编号和重复号的培养皿；支持一天多次批量巡检、累计发芽数与发芽率动态派生、`per_dish` / `per_material` 前 N 株样本及 SeedlingSample 来源追踪，并提供巡检纠错和审计。

## Stage 2.5 — Bootstrap & Account Management（已发布，v0.3.1）

首次部署通过服务器本机一次性初始化码和浏览器创建首位管理员；管理员管理成员、临时密码与账号状态，成员可自助改密。本阶段未改发芽实验业务。

## v0.3.2 — Manual Workflow & Usability Closeout（已完成、已发布）

第一轮提高界面可读性、统一中文名优先、明确实验状态主流程，并提供单独的物种及批次导入。第二轮增加种子材料一体导入及整表增量识别、按物种分组的批次与材料选择、中文名拼音排序、实验内编号确认和置床清单、可跨多日的培养皿实际置床、批次共享时间的局部发芽巡检、多实验联合导出。后续人工测试收口增加两种无原始材料编号导入模式、批量确认、主要列表分页、大窗口材料选择器、实验执行紧凑概览及材料进度分页、发芽率汇总和安全删除规则；预计最晚完成日期暂不在主要界面显示。v0.3.2 已完成并发布；其后的 Stage 3 — Seedling Measurement / 幼苗测定闭环已随 v0.4.0 正式发布。界面文案遵循仓库 `AGENTS.md` 的长期约定。

## Stage 3 — Seedling Measurement / 幼苗测定闭环（已发布，v0.4.0）

DAG 今日及逾期任务、根长苗长录入、材料级分页工作台、测定记录查询、纠错、原始数据导出与审计；已补齐生命周期、终止原因、导入衔接、测定进度排序与响应式布局，并完成最终项目卫生；已正式发布 v0.4.0。

## Stage 3.5 — Production Trial Deployment（v0.4.1）

单端口生产部署、Windows 运行控制中心、本机/局域网/远程 HTTPS 入口、独立程序与数据目录、正式 SQLite 在线备份、首次部署向导、portable、单实例、登录启动与实例隔离完成收口，形成生产试运行版。

## v0.5.0 — 实验身份、历史验证与科研导出（2026-10-03 收口，发布候选）

已实现 GER 实验类型、优先计划开始年月的新实验编号、旧 EXP 编号保留、统一现场培养皿和幼苗完整编号，以及未记录与明确巡检 0 的区分。功能已 fast-forward 合入 main，VERSION 为 0.5.0；本阶段仅实验类型迁移，发布准备不新增迁移，tag / GitHub Release 等待单独授权。

已实现历史 200 份材料的临时回填能力验证工具，默认 dry-run，apply 仅写一次性空业务测试库，完成数量、逐值与正式 Excel 反向核账后才提交。科研长宽表共用只读计划槽位服务，历史数据宽表为 2000 行、长表为 6000 行，数据库仍只保存 1665 株真实幼苗和 4955 条实测。未来分析从设计全集 LEFT JOIN 真实事实；本阶段不实现统计分析。

正式历史数据生产导入、干重、Stage 4 统计分析、发芽观察结束闭环和最终 Project Hygiene 尚未完成；数据库恢复和升级器也仍未实现，不计入 v0.5.0 能力。

## 下一维护任务 — Legacy Backfill

历史 200 份材料已在一次性临时库完成回填与核账验证，尚未导入正式业务库。正式历史导入后续单独确认：按历史实际计划日期创建 GER 实验并保持进行中，保存发芽时间及 3/7/14 DAG 根苗长；实际测定时间严格为 germinated_at + DAG，不作推定。现有验证工具的临时目录、空业务库、原文件只读和事务回滚保护不得放宽。干重独立开发；最终完整 Project Hygiene 在正式回填核账后单独执行。

## 后续增量

- Stage 4：数据统计分析、派生指标、图表、导出与历史履历；尚未开始。

GBIF/WFO/COL、WinRHIZO、仪器连接、标签/二维码、复杂 Treatment、邮件与审核工作流均另行评估，不提前建设空模块。

## Stage 3 发布收口（2026-10-01）

功能与两轮人工 UX 验收、最终历史排序小修、项目卫生均已完成。测试和文档按长期业务用途整理；当前人工测试库及在线验收快照保留，历史验证产物清理，开发重置备份最多保留最新 3 份有效文件。Stage 3 随 v0.4.0 正式发布。Stage 4 尚未开始。
