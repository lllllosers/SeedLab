# 人工测试与开发数据重置（Stage 3.1，未发布）

## 人工测试建议

优先建立少量物种、批次与实验，验证分日置床、巡检新增0、同日多次、前N株来源、材料级连续测定、修改、清除与多材料记录查询。检查根长 Enter → 苗长 Enter → 保存下一株 → 根长聚焦；搜索变化不丢失右侧正在填写的值。完成/终止流程请用独立测试实验，终止后只读且不能恢复执行。

自动 pytest 使用 `tmp_path` 和系统临时目录，不能重置当前人工测试库。当前开发库 `backend/data/seedlab.db` 不会被本阶段自动清空。

## 预览与执行

在仓库根目录运行：

```powershell
.\scripts\reset_dev_data.ps1 -DryRun
.\scripts\reset_dev_data.ps1
# 已明确决定删除业务数据时才使用：
.\scripts\reset_dev_data.ps1 -Yes
```

也可双击根目录 `reset_dev_data.bat`；默认显示各类业务数据数量并要求输入 `RESET`，不会默认无提示清库。取消或关闭输入将保留数据。

在 backend 目录使用 CLI：

```powershell
..\.venv\Scripts\python.exe -m app.cli reset-dev-data --dry-run
..\.venv\Scripts\python.exe -m app.cli reset-dev-data
..\.venv\Scripts\python.exe -m app.cli reset-dev-data --yes
```

只能在 `SEEDLAB_ENV=development` 执行，任何其他环境（包括 production）直接拒绝：“正式环境禁止执行开发数据库重置。”没有绕过参数；`--yes` 只跳过交互确认，不跳过环境检查、备份或事务。

## 保留与删除

保留账号、密码、管理员权限、使用状态、当前登录信息和数据库迁移版本。真实表名是 `users`、`sessions`（对应 SessionToken）和 `alembic_version`。`bootstrap.token` 文件保持原样。

删除操作记录、幼苗测定、幼苗样本、发芽巡检、培养皿、测定时间、实验材料、默认方案、实验、材料导入记录、种子批次和物种。按外键依赖倒序，在一个事务里全部完成；任何失败回滚，不会删一半。如果发现 ORM 未登记的未知表，停止并要求先核对。

## 在线备份

执行前使用 SQLite backup 接口生成一致性备份，支持正在使用 WAL 的数据库；不直接复制主文件。默认开发库的备份保存在 `backend/backups/dev-reset-YYYYMMDD-HHMMSS-随机后缀.db`。其他位置的临时测试库备份保存到该库相邻的 `backups/`。备份完成且完整性检查通过后才进入删除事务；备份失败不删除。删除后检查 foreign_key_check；已有备份永不由清理工具删除。

恢复前先停开发服务，保留当前库和WAL/SHM，使用独立副本核对备份后再人工决定恢复；此工具不提供自动恢复或删除备份操作。
