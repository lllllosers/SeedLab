# 人工测试、项目卫生与开发数据重置

本文件是人工测试、开发重置和项目卫生方法的权威来源，保留长期操作流程及安全边界。当前开发阶段见[路线图](03_开发路线图.md)，自动质量门见[开发说明](04_开发与运行说明.md)。

## 人工测试与数据保护

使用少量独立实验核对分日置床、巡检新增 0、同日多次、前 N 株来源、材料级连续测定、修改、清除与多材料记录查询。根长 Enter → 苗长 Enter → 保存下一株 → 根长聚焦；搜索不丢失正在填写的值。完成或终止流程使用独立测试实验，终止后只读且不能恢复执行。

检查材料选择的 25/50/100 分页、预计编号、导入全部/新增材料进入正常七步向导、筛选清除、物种与批次总表的中文列和文本编号。工作台在 1366×768、1440×900、1536×864、1920×1080 的 100% 缩放下检查可读性、输入聚焦、默认折叠进度与页面宽度。以 2 个培养皿、每皿 3 株幼苗和 DAG 0/1/3 核对全部 18 个任务沿培养皿 → 幼苗 → DAG 排序，已测与未测、0 与 NA 清楚区分；未测任务不能从记录表创建测定。

正式 pytest 使用 `tmp_path`、系统临时目录和 BytesIO，不重置当前人工测试库。`run_tests.bat` 默认创建独立的系统临时目录，测试子进程结束后清理，避免沿用 Windows 上旧 pytest 临时目录的权限；显式指定 `--basetemp` 时尊重该参数。迁移往返和浏览器自动化使用隔离数据库，截图和诊断报告写到系统 TEMP，不在项目数据目录永久留存。

## 三个维护工具

在仓库根目录运行：

```powershell
# 只读，不删除文件，不打开数据库，不修改权限
.\scripts\project_hygiene_check.ps1

# 预览安全白名单缓存清理
.\scripts\clean_dev_artifacts.ps1 -DryRun
# 确认预览后执行
.\scripts\clean_dev_artifacts.ps1

# 仅查看开发业务重置范围，不删除数据
.\scripts\reset_dev_data.ps1 -DryRun
```

只读卫生工具通过与应用相同的 Settings 解析配置，从 backend 工作目录解析 SQLite 相对路径，不根据文件名猜主库。输出当前分支/状态、实际数据库、data 中数据库、备份分类与数量、缓存、依赖环境和主要目录大小、最大 20 文件、超过 100 MiB 的文件、Git 对象大小及 ignore 摘要；无管理员权限要求。

缓存清理只处理明确的 `.test-temp-*`、`.tmp-pytest-*`、`.tmp-round2-*` 根级临时目录，以及源码内准确命名的 Python/pytest/ruff/mypy 缓存、pyc、指定位置的 dist、覆盖率与浏览器报告。不处理未知 `.tmp-*`、数据库、用户数据、备份、依赖环境或运行文件。递归源码扫描明确跳过build和dist，三套正式分发目录不会被缓存工具触及；单独列入白名单的frontend/dist仍属于可清理前端构建输出。删除前核对仓库路径边界、tracked 文件和目录内链接；发现链接或 tracked 文件保留并报告。迁移源码完整保留，迁移目录只清理准确命名的缓存。

`.venv`、`frontend/node_modules` 和 editable 安装生成的 egg-info 是可重新生成且被忽略的本地开发环境，保留以便继续开发。缓存清理、只读卫生检查和业务重置职责独立。

## 开发业务重置：明确确认才执行

```powershell
.\scripts\reset_dev_data.ps1
# 已明确决定删除开发业务数据时才使用
.\scripts\reset_dev_data.ps1 -Yes
```

也可双击 `reset_dev_data.bat`，默认显示数量并要求输入 `RESET`；取消或关闭输入保留数据。在 backend 目录可使用：

```powershell
..\.venv\Scripts\python.exe -m app.cli reset-dev-data --dry-run
..\.venv\Scripts\python.exe -m app.cli reset-dev-data
..\.venv\Scripts\python.exe -m app.cli reset-dev-data --yes
```

只能在 `SEEDLAB_ENV=development` 执行，其他环境直接拒绝。`--yes` 只跳过交互确认，不跳过环境检查、备份或事务。AF-0 不执行开发重置；质量门只使用测试自行创建的隔离数据库。

保留账号、密码、权限、使用状态、登录会话、`alembic_version` 和 `bootstrap.token`。业务删除包括审计、测定、样本、巡检、培养皿、时间点、实验材料/方案/实验、导入记录、批次和物种，按外键依赖倒序在一个事务完成；任何失败回滚。发现未知表则停止核对。

## 一致性备份与最近 3 份保留策略

以下是既有开发重置工具的恢复保护行为，AF-0 仅记录现状，不增加测试数据长期备份制度。可重新生成的测试库和验收输出完成验证后清理；正式长期备份对象仍只有不可替代的业务数据库。

重置前复用 SQLite 在线 backup 接口，支持 WAL，不直接复制主文件；检查 integrity_check 和 foreign_key_check 后才删除业务数据。默认开发库备份位于 `backend/backups/dev-reset-YYYYMMDD-HHMMSS-随机后缀.db`，其他位置的测试库使用相邻 backups 目录。

**仅成功提交开发重置后**，按文件修改时间和文件名排序，保留最新 **3 份有效、独立的 `dev-reset-*.db`**。自动淘汰只匹配此命名，不处理手工快照、生产备份或未知文件。存在链接、WAL/SHM/journal 附属文件、完整性或外键检查失败的候选保留，等待人工核对。淘汰成功输出 `[PRUNE]`；核对或删除失败输出 `[KEEP]`，不影响已经成功的重置。失败重置和 dry-run 均不淘汰旧备份。

`stage3-final-acceptance-*.db` 等旧手工验收快照不参与开发 reset 自动淘汰。清理前必须核对内容、当前配置、源码/脚本引用及实际运行占用，确认它们全为开发/验收产物；不能依据文件名或所在目录误删正式数据。build/、dist/ 是可重建产物而非备份，源码由 Git 保存，不建立 source-backup、pre-refactor 或 stage-final 副本。已验收正式分发目录须按当前任务授权保护，不由一般缓存清理删除。

生产备份策略以[生产运维](10_生产部署与控制中心设计.md)为准。开发恢复前先停服务，保留当前库及 WAL/SHM，检查选定备份后人工决定恢复；工具不自动恢复。一次性清理盘点和验收日志由 Git 历史追溯，不作为当前操作依据。
