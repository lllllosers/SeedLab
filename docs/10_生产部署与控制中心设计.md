# 生产部署与控制中心设计

## 当前阶段

v0.4.0 已完成 Stage 3，可进入试运行准备。Stage 3.5 已建立单端口生产服务、浅色 Control Center 与服务生命周期管理，本轮完成 Phase 3 的访问模式、持久化设置、正式备份及数据库健康检查，等待人工验收。应用版本仍为 0.4.0，不新增数据库迁移；便携包、升级和恢复尚未实现，Stage 4 统计分析不属于本阶段。

## 已实现：单端口生产服务

```text
浏览器 → http://127.0.0.1:8848 → FastAPI / Uvicorn
                                  ├─ /api/*：业务接口
                                  └─ Vue 预构建静态页面
```

- 开发继续使用 `run_dev.bat`：Vite 5173、FastAPI 8000，开发 `/docs` 可用。
- 构建阶段执行 `scripts/build_production.ps1`，生成 `frontend/dist`。构建需要 Node.js 与已安装的前端依赖；脚本不会自动安装依赖。
- 命令行启动执行 `run_prod.bat` 或 `python scripts/run_prod.py`；也可通过控制中心启动。服务仅运行 Python，不运行 npm、Vite、TypeScript，也不检查或使用 node_modules。
- 启动先检查 Python 环境及前端 `index.html`，再执行 `alembic upgrade head`。前端缺失或迁移失败时不启动服务；首次空库仍生成本机初始化码。
- 默认监听 `127.0.0.1:8848`，仅本机访问。可显式指定 `--host 0.0.0.0` 进行局域网测试，或用 `--port` 更换端口；单 worker，不启用 reload，Ctrl+C 停止。
- `/api/health` 保持原有状态与版本响应。生产关闭 `/docs` 和 OpenAPI 文档；开发文档保持可用。

## 前端目录与页面路由

`SEEDLAB_WEB_ROOT` 配置已构建的前端目录，默认 `frontend/dist`。绝对路径直接使用；相对路径以项目根目录为基准，与启动时所在目录无关。`--web-root` 优先于环境变量及 `.env`。未来便携包可显式指定 `app/web`，当前尚未实现打包。

StaticFiles 对真实静态文件做目录边界检查，不跟随指向目录外的符号链接。普通无文件扩展名路径的 GET/HEAD 请求在没有真实静态文件时统一返回 `index.html`；Vue Router 是页面路由的唯一事实源，负责页面匹配和未知页面跳转。直接输入地址、刷新均由 Vue Router 接管，新增前端页面无需同步 Python 路由列表。

未知 `/api` 或 `/api/*` 保留 JSON 404，生产 `/docs` 和 `/openapi.json` 返回 404。`/assets/*` 缺失资源及其他明显文件请求（如 `.css`、`.js`、`.xlsx`）返回 404。路径穿越、反斜杠和目录外符号链接请求也返回 404，不进入页面回退。前端 API 继续使用同源相对路径 `/api`，开发由 Vite 转发。

## 访问模式与认证

控制中心提供三种互斥模式，端口默认 8848。普通页面路由仍只由 Vue Router 定义。

| 访问方式 | 服务监听 | 内部健康检查 | 用户访问入口 | Cookie Secure |
| --- | --- | --- | --- | --- |
| 仅本机使用 | 127.0.0.1 | http://127.0.0.1:8848/api/health | http://127.0.0.1:8848 | false |
| 局域网共享 | 0.0.0.0 | 同上 | http://所选IPv4:8848 | false |
| 远程访问 | 127.0.0.1 | 同上 | 已保存的 HTTPS 根地址 | true |

控制中心启动子进程时明确传入 production、Cookie Secure、实际数据库和初始化码路径；会话、账号和权限规则沿用后端实现。开发 `.env` 不被改写。命令行 runner 仍使用原有参数与环境变量，不代替控制中心读取设置。

## 已实现：Control Center 骨架与服务生命周期

在项目根目录安装可选依赖并启动：

```powershell
.\.venv\Scripts\python.exe -m pip install -e './backend[test,control]'
.\scripts\build_production.ps1
.\run_control_center.bat
```

PySide6 仅属于 `control` 可选依赖，服务器无需 Qt。当前验证使用 6.8.3，依赖范围限定 6.8 稳定系列；6.11.2 在本机 Miniconda 环境出现 Qt DLL 加载问题，不在本阶段支持范围内。控制中心启动入口可能短暂保留一个开发终端，启动服务器不会再弹新的 CMD；最终 windowed EXE 留待打包阶段。

`control_center/` 分离路径解析、非 QWidget 的进程管理、窗口、QSS 和复用卡片，SVG 图标为项目自绘。六页包含概览、运行管理、网络访问、数据与备份、日志与诊断、设置与关于；网络访问、正式备份与设置已接入；诊断包等未实现能力仅展示状态。

- 默认窗口约 1180×720，根据可用屏幕的逻辑尺寸缩小。较小可用区域的最小尺寸也随之缩小，页面支持纵向滚动；Qt 默认支持 Windows DPI 缩放。常规最小目标为 980×620。
- 按已读取的配置监听本机或局域网地址。使用当前 `.venv` Python 创建隐藏子进程，Windows 设置 `CREATE_NO_WINDOW`；迁移子进程同样隐藏。启动、停止和重启期间禁用冲突操作。
- `QNetworkAccessManager` 每 1.5 秒异步检查健康状态，单次最多等待 1.2 秒；仅状态 ok 且版本与唯一 VERSION 一致时识别 SeedLab。启动最多等待 20 秒；失败展示业务语言并可查看日志。
- 已有相同版本服务时显示“检测到 SeedLab 已在运行”，只允许打开浏览器，不猜测 PID、不接管或停止外部服务。其他程序占用端口时提示关闭占用程序后重试。
- 每次启动生成独立 `%TEMP%/SeedLab/control/<uuid>.stop` 路径，停止时创建信号文件。runner 的异步检查设置正常退出标志，完成当前请求与 lifespan 后退出，随后清理文件；没有新增 shutdown API。命令行不传 `--stop-file` 时继续支持 Ctrl+C。
- 停止等待 10 秒后提供“继续等待 / 强制结束”，不会自动强杀。只有用户明确选择强制结束才结束本控制中心拥有的进程（Windows 包含其子进程）。重启先等待旧服务退出，再启动新服务。
- 首次管理员未设置时显示初始化提示，初始化码默认遮蔽，支持主动显示/复制并打开 `/setup`；文件消失或初始化状态变为已完成时提示消失，初始化码不写日志。
- X 隐藏至托盘，每次运行只通知一次；托盘菜单与主界面按钮同步。退出拥有运行中服务时要求“停止 SeedLab 并退出 / 取消”，等待正常退出后再关闭控制中心。若系统托盘不可用则最小化窗口，不隐藏为不可恢复状态。
- 服务和控制中心日志分别位于项目根目录 `logs/production-server.log`、`logs/control-center.log`，UTF-8，每份最多 5 MB，最多保留当前文件和两份轮换文件。敏感值在写入前过滤；界面只显示最近事件摘要，技术堆栈在详细文件中。
- 概览数据库卡片显示有效路径、文件名与大小；完整检查和备份通过后台任务执行，不修改业务记录。

未接入：数据库恢复、诊断包、开机启动、升级、portable 打包和 Stage 4。

## 已实现：持久化运行设置

配置路径集中在 RuntimePaths，默认 `config/seedlab.json`，真实配置已被 Git 忽略；仓库只保存 `config/seedlab.example.json`。这是部署设置，不包含密码、初始化码、会话、CSRF 或 SakuraFrp Token。

```json
{
  "schema_version": 1,
  "access_mode": "local",
  "port": 8848,
  "lan_address": null,
  "remote_url": null,
  "auto_backup_enabled": true,
  "auto_backup_retention": 14
}
```

缺文件时使用安全默认值，第一次明确保存时才创建文件。省略的已知字段使用默认值；未知字段、未知 schema、非法 JSON、错误类型、非法地址或保留份数均拒绝加载。原文件保留，网络页和设置页显示安全本机模式警告，日志记录原因；只有用户主动保存才覆盖损坏文件。

保存先在同目录写唯一临时文件，flush、fsync 后 os.replace 原子替换；失败清理该临时文件，内存和原文件均保持原值。保留份数允许 1～90，默认 14；端口显示为只读。设置草稿跨页面保留，有未保存提示。X 仍只隐藏到托盘；真正退出时提供保存、不保存、取消。

运行中修改访问方式必须确认“保存并重启”，等待旧服务退出后使用新设置。已保存配置与当前服务配置各自保留快照，重启前显示旧运行方式。外部服务不会被接管或停止；新设置只在下次由控制中心启动时生效，外部状态不宣称其访问模式已受本控制中心配置。

## 已实现：局域网与远程入口

Qt 枚举启用且运行中的网卡 IPv4，过滤回环、未指定、APIPA 等不可用地址。常见虚拟网络放到列表后面并标注“其他网络”，仍可选择。已保存地址失效时推荐当前地址并提示，不自动写配置；没有地址时不能启动局域网模式。同网设备连接失败时请检查网络与 Windows 防火墙，控制中心不会更改防火墙。

远程地址仅接受 HTTPS 根地址（可带端口）；去除首尾空白及末尾斜杠，拒绝账号、路径、查询参数、片段及其他协议。远程模式普通“打开 SeedLab”始终使用 HTTPS 入口，本机 HTTP 只供内部健康检查和隧道使用。

远程检测使用 QNetworkAccessManager 异步请求 `/api/health`，超时 5 秒，不跟随重定向，不忽略 SSL 错误，保留 Qt 的证书链与主机名验证。只有 status=ok 且 version 等于唯一 VERSION 才算成功；无法连接、非 SeedLab 和其他版本分别提示。远程连接状态独立于本机服务状态，不持久化。人工检测及状态变化记事件，定时重复检测不刷日志；运行中远程模式每 30 秒检测一次。

访问地址和初始化码复制统一仅尝试 clipboard.setText；捕获写入异常，不以即时读取剪贴板是否相同作为成功条件。初始化码不写日志。

## 已实现：正式 SQLite 备份与检查

通用备份服务位于 `backend/app/services/sqlite_backup.py`，不复用开发重置工具的业务逻辑。SQLite Connection.backup 从只读源连接生成一致性快照，支持源连接仍打开且使用 WAL；不直接复制主库文件。后台线程先写唯一 partial 文件，检查 integrity_check 和 foreign_key_check，关闭连接、fsync 后原子发布。在线复制超过两分钟会终止并清理本次临时文件。最终文件不会覆盖同名备份；极少数同秒冲突添加 8 位随机后缀。失败仅清理本次 partial 及其 sidecar，不产生伪成功文件。

```text
backups/
├─ auto/             seedlab-auto-YYYYMMDD-HHMMSS.db
├─ manual/           seedlab-manual-YYYYMMDD-HHMMSS.db
└─ before-upgrade/   仅预留，本轮没有升级流程
```

首次备份才建立新目录。现有根目录或 backend/backups 中的开发、验收和手工快照原样保留，不移动、不重命名、不参与整理。

每天按 Asia/Shanghai 日期，在本控制中心拥有的服务首次成功运行后检查当天有效自动备份；已有有效文件则不重复。关机后重新启动同日也不会重复；非固定凌晨任务，不修改系统时间。仅识别到外部服务时不执行自动备份，因为其数据库配置可能不同。自动备份失败不会停止服务，页面提示并记录详细原因。

按份数保留最新 14 份有效自动备份，可在设置页调整为 1～90。只处理 auto 目录内严格命名、日期有效、普通文件、无符号链接/Windows reparse point、无 WAL/SHM/journal sidecar且完整性和外键检查通过的自动快照；删除前再次验证。目录祖先也拒绝重定向。未知文件、无效快照、manual、before-upgrade 和历史快照均不删除。快照验证使用只读 immutable 连接，避免产生 sidecar。

手工备份可在服务运行或停止时执行，永不被自动整理删除。页面显示最近文件名、时间（文件名中的实验室时间）和大小，并提供打开目录。数据库健康检查使用只读连接执行完整性与外键检查；失败提示停止录入并保留文件和备份，不自动修复。

备份、目录验证及健康检查通过独立 QThreadPool 后台串行任务执行；执行期间禁用相应按钮，结果通过 Qt 信号回到界面。退出等待正在执行的任务完成，避免留下半成品。

另一设备 LAN 尚未实测。用户确认本轮没有现成 SakuraFrp 隧道；真实远程 HTTPS 登录尚未实测。模拟检测覆盖连接正常、错误版本、非 SeedLab、连接失败及 SSL 握手失败；隔离服务验证远程模式产生 Secure Cookie，这不代表公网隧道已验收。
