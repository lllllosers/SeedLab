# 生产部署与控制中心设计

## 当前阶段

v0.4.0 已完成 Stage 3，可进入试运行准备。Stage 3.5 已建立单端口生产服务，并进入 Control Center 骨架与服务生命周期阶段。第一版浅色界面、健康检查、系统托盘、隐藏启动、优雅停止/重启及首次管理员提示已实现，等待人工 UI 验收。应用版本仍为 0.4.0，不新增数据库迁移；便携包及正式运维尚未完成，Stage 4 统计分析不属于本阶段。

## 已实现：单端口生产服务

```text
浏览器 → http://127.0.0.1:8848 → FastAPI / Uvicorn
                                  ├─ /api/*：业务接口
                                  └─ Vue 预构建静态页面
```

- 开发继续使用 `run_dev.bat`：Vite 5173、FastAPI 8000，开发 `/docs` 可用。
- 构建阶段执行 `scripts/build_production.ps1`，生成 `frontend/dist`。构建需要 Node.js 与已安装的前端依赖；脚本不会自动安装依赖。
- 命令行启动执行 `run_prod.bat` 或 `python scripts/run_prod.py`；也可通过控制中心启动。服务仅运行 Python，不运行 npm、Vite、TypeScript，也不检查或使用 node_modules。
- 启动先检查 Python 环境及前端 `index.html`，再执行 `alembic upgrade head`。前端缺失或迁移失败时不启动服务；首次空库仍生成本机初始化码。
- 默认监听 `127.0.0.1:8848`，仅本机访问。可显式指定 `--host 0.0.0.0` 进行局域网测试，或用 `--port` 更换端口；单 worker，不启用 reload，Ctrl+C 停止。
- `/api/health` 保持原有状态与版本响应。生产关闭 `/docs` 和 OpenAPI 文档；开发文档保持可用。

## 前端目录与页面路由

`SEEDLAB_WEB_ROOT` 配置已构建的前端目录，默认 `frontend/dist`。绝对路径直接使用；相对路径以项目根目录为基准，与启动时所在目录无关。`--web-root` 优先于环境变量及 `.env`。未来便携包可显式指定 `app/web`，当前尚未实现打包。

StaticFiles 对真实静态文件做目录边界检查，不跟随指向目录外的符号链接。普通无文件扩展名路径的 GET/HEAD 请求在没有真实静态文件时统一返回 `index.html`；Vue Router 是页面路由的唯一事实源，负责页面匹配和未知页面跳转。直接输入地址、刷新均由 Vue Router 接管，新增前端页面无需同步 Python 路由列表。

未知 `/api` 或 `/api/*` 保留 JSON 404，生产 `/docs` 和 `/openapi.json` 返回 404。`/assets/*` 缺失资源及其他明显文件请求（如 `.css`、`.js`、`.xlsx`）返回 404。路径穿越、反斜杠和目录外符号链接请求也返回 404，不进入页面回退。前端 API 继续使用同源相对路径 `/api`，开发由 Vite 转发。

## 访问模式与认证

本机模式默认 `127.0.0.1`；未来 Control Center 的局域网模式使用 `0.0.0.0`，本阶段仅提供显式 runner 参数。另一设备访问需使用主机局域网 IP；防火墙阻止时由开发人员记录，本轮脚本不修改防火墙。

`SEEDLAB_COOKIE_SECURE` 保持可配置，不因 production 自动改为 true。本机/可信局域网 HTTP 测试设为 false；HTTPS 访问设为 true。会话、初始化及权限规则沿用现有实现，无预设账号或密码。当前仍使用环境变量和 `.env`；正式 `config/seedlab.json` 留待 Control Center 接入。

## 已实现：Control Center 骨架与服务生命周期

在项目根目录安装可选依赖并启动：

```powershell
.\.venv\Scripts\python.exe -m pip install -e './backend[test,control]'
.\scripts\build_production.ps1
.\run_control_center.bat
```

PySide6 仅属于 `control` 可选依赖，服务器无需 Qt。当前验证使用 6.8.3，依赖范围限定 6.8 稳定系列；6.11.2 在本机 Miniconda 环境出现 Qt DLL 加载问题，不在本阶段支持范围内。控制中心启动入口可能短暂保留一个开发终端，启动服务器不会再弹新的 CMD；最终 windowed EXE 留待打包阶段。

`control_center/` 分离路径解析、非 QWidget 的进程管理、窗口、QSS 和复用卡片，SVG 图标为项目自绘。六页包含概览、运行管理、网络访问、数据与备份、日志与诊断、设置与关于；网络/备份/诊断包等未接入能力仅展示只读状态，不提供伪操作按钮。

- 默认窗口约 1180×720，根据可用屏幕的逻辑尺寸缩小。较小可用区域的最小尺寸也随之缩小，页面支持纵向滚动；Qt 默认支持 Windows DPI 缩放。常规最小目标为 980×620。
- 仅监听本机 `127.0.0.1:8848`。使用当前 `.venv` Python 创建隐藏子进程，Windows 设置 `CREATE_NO_WINDOW`；迁移子进程同样隐藏。启动、停止和重启期间禁用冲突操作。
- `QNetworkAccessManager` 每 1.5 秒异步检查健康状态，单次最多等待 1.2 秒；仅状态 ok 且版本与唯一 VERSION 一致时识别 SeedLab。启动最多等待 20 秒；失败展示业务语言并可查看日志。
- 已有相同版本服务时显示“检测到 SeedLab 已在运行”，只允许打开浏览器，不猜测 PID、不接管或停止外部服务。其他程序占用端口时提示关闭占用程序后重试。
- 每次启动生成独立 `%TEMP%/SeedLab/control/<uuid>.stop` 路径，停止时创建信号文件。runner 的异步检查设置正常退出标志，完成当前请求与 lifespan 后退出，随后清理文件；没有新增 shutdown API。命令行不传 `--stop-file` 时继续支持 Ctrl+C。
- 停止等待 10 秒后提供“继续等待 / 强制结束”，不会自动强杀。只有用户明确选择强制结束才结束本控制中心拥有的进程（Windows 包含其子进程）。重启先等待旧服务退出，再启动新服务。
- 首次管理员未设置时显示初始化提示，初始化码默认遮蔽，支持主动显示/复制并打开 `/setup`；文件消失或初始化状态变为已完成时提示消失，初始化码不写日志。
- X 隐藏至托盘，每次运行只通知一次；托盘菜单与主界面按钮同步。退出拥有运行中服务时要求“停止 SeedLab 并退出 / 取消”，等待正常退出后再关闭控制中心。若系统托盘不可用则最小化窗口，不隐藏为不可恢复状态。
- 服务和控制中心日志分别位于项目根目录 `logs/production-server.log`、`logs/control-center.log`，UTF-8，每份最多 5 MB，最多保留当前文件和两份轮换文件。敏感值在写入前过滤；界面只显示最近事件摘要，技术堆栈在详细文件中。
- 数据库卡片仅显示有效数据库路径、文件名、大小，不查询业务表、不创建备份、不修改数据。
